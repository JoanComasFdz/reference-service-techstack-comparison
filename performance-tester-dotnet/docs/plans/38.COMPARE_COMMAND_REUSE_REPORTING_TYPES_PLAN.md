# Plan 38: Single Types for JSON Serialization and Deserialization

## Problem

Three separate places manually parse JSON with `JsonElement.GetProperty()` field-by-field:

1. **`CompareCommand`** — reads supplementary files into runtime types
2. **`ChartDataLoader`** — reads supplementary files into JSON DTO types
3. **`ReportGenerator`** — writes using **anonymous types** instead of the actual DTO records

Meanwhile, the Reporting project has *two parallel hierarchies* of nearly identical types:

| Runtime type (Shared/Models) | JSON DTO (ReportGeneration/Models) | Difference |
|---|---|---|
| `ProcessResourceSample` (`DateTime Timestamp`, `ElapsedSeconds`, `CpuPercent`, `MemoryRssMb`, `Threads`) | `ProcessResourceSampleJson` (`string Timestamp`, `ElapsedSeconds`, `CpuPercent`, `MemoryRssMb`, `Threads`) | Only `Timestamp` type |
| `SystemResourceSample` (`DateTime Timestamp`, `ElapsedSeconds`, ...) | *(no type — anonymous object)* | JSON type doesn't exist |
| `ThroughputMetricSample` (`DateTime`, `Rate`, `CumulativeCount`) | `ThroughputSampleJson` (`string`, `EventsPerSecond`, `TotalEvents`) | `Timestamp` type + different field names |

**Root causes:**
1. JSON DTOs use `string Timestamp` instead of `DateTime` — even though `Iso8601DateTimeConverter` exists and handles conversion
2. `ReportGenerator` doesn't use its own DTO types — it serializes anonymous objects, making the DTOs dead code for serialization
3. `ReportGenerator` omits `elapsed_seconds` from resource-metrics and system-metrics JSON, forcing CompareCommand to recalculate it

## Scope

Fix events-throughput, resource-metrics, and system-metrics. **Leave api-throughput as-is** (keep `LoadThroughputSamplesAsync` for API data, which uses `calls_per_second` / `total_calls`).

## Solution

### Step 1: Delete `ProcessResourceSampleJson` — use `ProcessResourceSample` directly

`ProcessResourceSampleJson` is identical to `ProcessResourceSample` except for `string` vs `DateTime` on `Timestamp`. Since `Iso8601DateTimeConverter` handles the conversion, `ProcessResourceSample` can serve as the JSON type directly.

**In `ResourceMetricsReport.cs`:**
- Delete `ProcessResourceSampleJson` (lines 96-122)
- Update `ProcessResourceMetricsReport.Samples` from `IReadOnlyList<ProcessResourceSampleJson>` to `IReadOnlyList<ProcessResourceSample>`
- Change `ProcessResourceMetricsReport.TestDate` from `string` to `DateTime`

**Before:**
```csharp
public sealed record ProcessResourceMetricsReport
{
    public required string TestDate { get; init; }
    public required int SamplingIntervalMs { get; init; }
    public required IReadOnlyList<ProcessResourceSampleJson> Samples { get; init; }
    public required ResourceSummary CpuSummary { get; init; }
    public required ResourceSummary MemorySummary { get; init; }
}

public sealed record ProcessResourceSampleJson
{
    public required string Timestamp { get; init; }
    public required double ElapsedSeconds { get; init; }
    public required double CpuPercent { get; init; }
    public required double MemoryRssMb { get; init; }
    public required int Threads { get; init; }
}
```

**After:**
```csharp
public sealed record ProcessResourceMetricsReport
{
    public required DateTime TestDate { get; init; }
    public required int SamplingIntervalMs { get; init; }
    public required IReadOnlyList<ProcessResourceSample> Samples { get; init; }
    public ResourceSummary? CpuSummary { get; init; }
    public ResourceSummary? MemorySummary { get; init; }
}

// ProcessResourceSampleJson deleted — ProcessResourceSample (Shared/Models) is the single type
```

Note: `CpuSummary`/`MemorySummary` become nullable because the JSON uses a flat `summary` object with mixed fields (`avg_cpu_percent`, `avg_memory_rss_mb`, etc.), not nested `cpu_summary`/`memory_summary` objects. Making them nullable means deserialization won't fail when the JSON structure doesn't match; CompareCommand doesn't need summaries anyway (it computes its own from samples). The serialization side won't change — ReportGenerator still writes the summary via anonymous type (fixing that is a separate concern).

### Step 4: Create `SystemMetricsReport` wrapper type

No wrapper exists for system-metrics.json. Create one using `SystemResourceSample` directly (same as what we did for process resources).

**New file: `PerformanceTester.Reporting/ReportGeneration/Models/SystemMetricsReport.cs`**

No separate `SystemResourceSampleJson` — we use `SystemResourceSample` directly.

### Step 5: Fix `ReportGenerator` — write `elapsed_seconds` and serialize proper types for samples

Currently `ReportGenerator` omits `elapsed_seconds` from resource-metrics and system-metrics samples. This forces CompareCommand to recalculate it from `timestamp - test_date`. Fix: include it in the JSON.

The overall approach for each report method: serialize samples using the actual model types instead of anonymous objects. The summaries can remain as anonymous types (they have format-specific field names like `avg_cpu_percent` that don't map to any generic type, and fixing that is out of scope).

**`GenerateProcessResourceMetricsReportAsync` — before (anonymous types):**
```csharp
samples = testReport.ProcessResourceSamples.Select(s => new
{
    timestamp = s.Timestamp.ToString("yyyy-MM-ddTHH:mm:ss.ffffff"),
    cpu_percent = Math.Round(s.CpuPercent, 2),
    memory_rss_mb = Math.Round(s.MemoryRssMb, 2),
    threads = s.Threads
}).ToList(),
```

**After (proper types + `elapsed_seconds`):**
```csharp
samples = testReport.ProcessResourceSamples.Select(s => new ProcessResourceSample
{
    Timestamp = s.Timestamp,
    ElapsedSeconds = Math.Round(s.ElapsedSeconds, 3),
    CpuPercent = Math.Round(s.CpuPercent, 2),
    MemoryRssMb = Math.Round(s.MemoryRssMb, 2),
    Threads = s.Threads
}).ToList(),
```

`SnakeCaseLower` handles the property name mapping. `Iso8601DateTimeConverter` handles timestamp formatting. `ElapsedSeconds` is now written to JSON (backward-compatible addition).

**Same pattern for `GenerateSystemMetricsReportAsync`** — serialize `SystemResourceSample` directly instead of anonymous type.

**For `GenerateEventsThroughputReportAsync`** — the samples are already written with `elapsed_seconds`. Serialize `ThroughputSampleJson` instead of anonymous type. Map from `ThroughputMetricSample`:
```csharp
samples = testReport.EventsThroughputSamples.Select(s => new ThroughputSampleJson
{
    Timestamp = s.Timestamp,
    ElapsedSeconds = Math.Round(s.ElapsedSeconds, 3),
    EventsPerSecond = Math.Round(s.Rate, 2),
    TotalEvents = s.CumulativeCount
}).ToList(),
```

### Step 6: Simplify `CompareCommand`

Replace manual `JsonElement` mapping with `JsonSerializer.Deserialize<T>()`.

**Events throughput — before:**
```csharp
var eventsThroughputSamples = await LoadThroughputSamplesAsync(
    $"{basePath}.events-throughput.json", "events_per_second", "total_events", cancellationToken);
```

**After:**
```csharp
var eventsThroughputSamples = await LoadEventsThroughputSamplesAsync(
    $"{basePath}.events-throughput.json", cancellationToken);
```

```csharp
private static async Task<IReadOnlyList<ThroughputMetricSample>> LoadEventsThroughputSamplesAsync(
    string filePath, CancellationToken cancellationToken)
{
    if (!File.Exists(filePath))
        return [];

    try
    {
        var json = await File.ReadAllTextAsync(filePath, cancellationToken);
        var report = JsonSerializer.Deserialize<ThroughputReport>(json, JsonOptions);
        if (report is null)
            return [];

        return report.Samples.Select(s => new ThroughputMetricSample
        {
            Timestamp = s.Timestamp,
            ElapsedSeconds = s.ElapsedSeconds,
            Rate = s.EventsPerSecond,
            CumulativeCount = s.TotalEvents
        }).ToArray();
    }
    catch { return []; }
}
```

Note: `ThroughputReport.Summary` is `required`, but the JSON summary fields (`avg_events_per_second`) don't match the C# property names (`AvgRate` → `avg_rate`). This means `JsonSerializer.Deserialize<ThroughputReport>` will fail because `required` properties on `ThroughputSummary` won't be populated.

**Fix:** Make `ThroughputReport.Summary` non-required with a default:
```csharp
public ThroughputSummary? Summary { get; init; }
```

This is safe because CompareCommand doesn't use the summary (it computes its own), and chart generation loads summary through `ChartDataLoader` (which parses it manually anyway). ReportGenerator writes the summary via anonymous type, so serialization is unaffected.

**Process resources — before:**
```csharp
var processResourceSamples = await LoadProcessResourceSamplesAsync(
    $"{basePath}.resource-metrics.json", cancellationToken);
```

**After:**
```csharp
private static async Task<IReadOnlyList<ProcessResourceSample>> LoadProcessResourceSamplesAsync(
    string filePath, CancellationToken cancellationToken)
{
    if (!File.Exists(filePath))
        return [];

    try
    {
        var json = await File.ReadAllTextAsync(filePath, cancellationToken);
        var report = JsonSerializer.Deserialize<ProcessResourceMetricsReport>(json, JsonOptions);
        if (report is null)
            return [];

        return report.Samples;
    }
    catch { return []; }
}
```

No mapping step needed — `report.Samples` is already `IReadOnlyList<ProcessResourceSample>`, and `ElapsedSeconds` is now in the JSON (Step 5).

**System metrics — same pattern** with `SystemMetricsReport` → `report.Samples` returns `IReadOnlyList<SystemResourceSample>` directly.

## Why this approach

**One type per concept:**
- `ProcessResourceSample` = the type, period. Used by runtime, serialization, and deserialization.
- `SystemResourceSample` = same.
- `ThroughputSampleJson` = the JSON-shaped type with domain-specific field names. Distinct from `ThroughputMetricSample` because the field names genuinely differ.

**No duplicate types:**
- `ProcessResourceSampleJson` deleted (was redundant)
- No new "deserialization DTOs" created

**Proper types:**
- `DateTime` instead of `string` for timestamps, everywhere
- `Iso8601DateTimeConverter` handles formatting for both read and write

**Fix the writer, not the reader:**
- Adding `elapsed_seconds` to JSON removes the need for CompareCommand to calculate it
- Serializing through real types instead of anonymous objects means the same types work for both directions
