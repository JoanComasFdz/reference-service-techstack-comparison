# 13.4 Orchestration API Abort Integration Tests

## Overview

This document outlines the integration tests needed to verify the new **API load test abort functionality** introduced in the staged changes. The abort feature allows the orchestrator to terminate API load tests early when too many consecutive failures occur.

## Summary of Staged Changes

The staged changes introduce API load test abort functionality with the following flow:

```
TestConfiguration.MaxConsecutiveApiFailures (default: 3, type: uint)
    ↓
TestOrchestrator.RunTestAsync()
    ↓
IApiLoadTester.StartTestAsync(maxConsecutiveFailures)
    ↓
K6ScriptGenerator.GenerateScript() → JavaScript with abort logic
    ↓
K6Executor.ExecuteAsync() → Handles exit code 108 (abort)
    ↓
K6ExecutionResult { Metrics, WasAborted, AbortReason }
    ↓
ApiLoadTestResult { ..., WasAborted, AbortReason }
```

### Key Changes by File

| File | Change |
|------|--------|
| `TestConfiguration.cs` | Added `MaxConsecutiveApiFailures` parameter (default: 3) |
| `TestOrchestrator.cs` | Passes `config.MaxConsecutiveApiFailures` to API load tester |
| `IApiLoadTester.cs` | Added `maxConsecutiveFailures` parameter to interface |
| `ApiLoadTestService.cs` | Implements abort handling, logs warnings for aborted tests |
| `ApiLoadTestResult.cs` | Added `WasAborted` and `AbortReason` properties |
| `K6ExecutionResult.cs` | New internal record for k6 execution results |
| `K6Executor.cs` | Handles k6 exit code 108 (abort), extracts abort reason |
| `K6ScriptGenerator.cs` | Generates k6 script with consecutive failure tracking |

## Gap Identified

**Important:** The `TestReport.ApiResults` record does NOT currently include `WasAborted` or `AbortReason` fields. The `ApiLoadTestResult` from the API load tester includes these fields, but they are not propagated to the final test report.

### Required Changes Before Tests

1. **Update `ApiResults` record** in `TestReport.cs`:
   ```csharp
   public sealed record ApiResults
   {
       // ... existing properties ...

       /// <summary>
       /// True if API load test was aborted early due to consecutive failures.
       /// </summary>
       public bool WasAborted { get; init; } = false;

       /// <summary>
       /// Reason for abort, if test was aborted.
       /// </summary>
       public string? AbortReason { get; init; }
   }
   ```

2. **Update `TestOrchestrator`** to propagate abort info from `ApiLoadTestResult` to `TestReport`

3. **Update `TestConfigurationBuilder`** to add `WithMaxConsecutiveApiFailures(uint)` method

4. **Enhance `ConfigurableReferenceService`** to support HTTP error responses

### Test 1: API Server Errors Trigger Abort

**Name:** `RunTestAsync_WhenApiServerReturnsErrors_ShouldAbortAndReportReason`

**Purpose:** Verify the orchestrator handles API abort scenarios gracefully and reports abort information in the test report.

**Setup:**
- Use `ConfigurableReferenceService` configured to return HTTP 500 errors on `/kpi` endpoint
- Use default `MaxConsecutiveApiFailures = 3`
- Short API duration (e.g., 10 seconds) to limit test time

**Test Flow:**
```
1. Start ConfigurableReferenceService with HTTP 500 responses
2. Run orchestrator with default abort threshold
3. k6 detects 3 consecutive failures
4. k6 aborts with exit code 108
5. Orchestrator captures abort info
6. Test report includes WasAborted=true and AbortReason
```

**Assertions:**
- Test completes without throwing exception (abort is handled gracefully)
- `report.Results.Phase3Api.ErrorCount > 0`
- `report.Results.Phase3Api.WasAborted == true`
- `report.Results.Phase3Api.AbortReason` contains "consecutive failures"
- `report.Results.Phase3Api.DurationSeconds < config.ApiDuration.TotalSeconds` (early termination)

**Why This Test:**
- Verifies the core new functionality works end-to-end
- Confirms abort is graceful (no exception thrown to caller)
- Validates abort reason is captured and reported

---

### Test 2: Abort Disabled Completes Full Duration

**Name:** `RunTestAsync_WhenAbortDisabled_ShouldCompleteFullDuration`

**Purpose:** Verify `MaxConsecutiveApiFailures = 0` disables abort behavior entirely.

**Setup:**
- Use `ConfigurableReferenceService` configured to return HTTP 500 errors
- Set `MaxConsecutiveApiFailures = 0` (disabled)
- Short API duration (e.g., 5 seconds) to limit test time

**Test Flow:**
```
1. Start ConfigurableReferenceService with HTTP 500 responses
2. Run orchestrator with abort disabled (MaxConsecutiveApiFailures = 0)
3. k6 encounters failures but never aborts
4. k6 runs for full configured duration
5. Test completes normally
```

**Assertions:**
- Test completes without abort
- `report.Results.Phase3Api.WasAborted == false`
- `report.Results.Phase3Api.AbortReason` is null
- `report.Results.Phase3Api.DurationSeconds` approximately equals configured duration (within 1-2s tolerance)
- `report.Results.Phase3Api.ErrorCount > 0` (failures occurred but didn't trigger abort)

**Why This Test:**
- Confirms the escape hatch (disabling abort) works correctly
- Important for users who want to run full-duration tests regardless of errors
- Validates the `0 = disabled` semantic is honored

---

### Test 3: Higher Threshold Tolerates More Failures

**Name:** `RunTestAsync_WithHigherAbortThreshold_ShouldTolerateIntermittentFailures`

**Purpose:** Verify custom `MaxConsecutiveApiFailures` threshold allows intermittent failures without aborting.

**Setup:**
- Use `ConfigurableReferenceService` that fails intermittently (e.g., every 3rd request returns 500)
- Set `MaxConsecutiveApiFailures = 10` (higher tolerance)
- API duration sufficient to see failure pattern (e.g., 10 seconds)

**Test Flow:**
```
1. Start ConfigurableReferenceService with intermittent failures (fail every 3rd request)
2. Run orchestrator with higher abort threshold
3. k6 encounters failures but they're not consecutive
4. Successful requests reset the consecutive failure counter
5. Test completes without abort
```

**Assertions:**
- Test completes without early abort
- `report.Results.Phase3Api.WasAborted == false`
- `report.Results.Phase3Api.ErrorCount > 0` (some failures occurred)
- `report.Results.Phase3Api.SuccessCount > 0` (some successes occurred)
- `report.Results.Phase3Api.DurationSeconds` approximately equals configured duration

**Why This Test:**
- Validates the threshold configuration works as expected
- Confirms consecutive counter resets on success (important behavior)
- Tests real-world scenario of intermittent failures

### 2. ConfigurableReferenceService Enhancement

Add HTTP response configuration to `ConfigurableReferenceService.cs`:

```csharp
private int _httpStatusCode = 200;
private int _failEveryNthRequest = 0;
private int _requestCount = 0;

/// <summary>
/// Configure the HTTP response status code for /kpi endpoint.
/// </summary>
public void ConfigureHttpResponse(int statusCode = 200)
{
    _httpStatusCode = statusCode;
    _failEveryNthRequest = 0;
}

/// <summary>
/// Configure intermittent failures (fail every Nth request).
/// </summary>
public void ConfigureIntermittentFailures(int failEveryNthRequest)
{
    _failEveryNthRequest = failEveryNthRequest;
    _httpStatusCode = 200; // Success by default
}

// In the /kpi endpoint handler:
private int GetResponseStatusCode()
{
    if (_failEveryNthRequest > 0)
    {
        _requestCount++;
        if (_requestCount % _failEveryNthRequest == 0)
            return 500;
        return 200;
    }
    return _httpStatusCode;
}
```

### 3. Custom Assertions

Add to `OrchestrationAssertions.cs`:

```csharp
/// <summary>
/// Asserts that the API load test was aborted due to consecutive failures.
/// </summary>
public static Task ApiLoadTestWasAborted(
    this AssertingThat<ITestOrchestrator> assertingThat,
    TestReport report,
    string expectedReasonContains)
{
    Assert.True(report.Results.Phase3Api.WasAborted,
        "API load test should have been aborted");
    Assert.NotNull(report.Results.Phase3Api.AbortReason);
    Assert.Contains(expectedReasonContains, report.Results.Phase3Api.AbortReason!);
    return Task.CompletedTask;
}

/// <summary>
/// Asserts that the API load test completed without abort.
/// </summary>
public static Task ApiLoadTestCompletedWithoutAbort(
    this AssertingThat<ITestOrchestrator> assertingThat,
    TestReport report)
{
    Assert.False(report.Results.Phase3Api.WasAborted,
        "API load test should not have been aborted");
    Assert.Null(report.Results.Phase3Api.AbortReason);
    return Task.CompletedTask;
}

/// <summary>
/// Asserts that the API load test duration is approximately as expected.
/// </summary>
public static Task ApiLoadTestDurationApproximately(
    this AssertingThat<ITestOrchestrator> assertingThat,
    TestReport report,
    TimeSpan expectedDuration,
    TimeSpan tolerance)
{
    var actualDuration = TimeSpan.FromSeconds(report.Results.Phase3Api.DurationSeconds);
    var minDuration = expectedDuration - tolerance;
    var maxDuration = expectedDuration + tolerance;

    Assert.InRange(actualDuration, minDuration, maxDuration);
    return Task.CompletedTask;
}
```

## Test File Template

```csharp
using Xunit;
using Xunit.Abstractions;
using PerformanceTester.Orchestration.IntegrationTests.Infrastructure;
using JoanComasFdz.AssertingThat;

namespace PerformanceTester.Orchestration.IntegrationTests;

public sealed class OrchestratorApiAbortTests(ITestOutputHelper output)
    : IntegrationTest(output)
{
    [Fact]
    public async Task RunTestAsync_WhenApiServerReturnsErrors_ShouldAbortAndReportReason()
    {
        // Arrange
        System.DotNetAotService.Stop();

        System.ConfigurableReferenceService.ConfigureHttpResponse(statusCode: 500);
        System.ConfigurableReferenceService.ConfigurePublication(
            eventCount: 10,
            warmupEventCount: 5);

        var config = new TestConfigurationBuilder()
            .WithEventCount(10)
            .WithWarmupEventCount(5)
            .WithApiDuration(TimeSpan.FromSeconds(10))
            .WithMaxConsecutiveApiFailures(3)
            .WithServicePort(9999)
            .WithDatabaseName(OrchestrationSystem.IntegrationTestDatabaseName)
            .Build();

        try
        {
            await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
            await System.ConfigurableReferenceService.ConnectAndSubscribeAsync(listenPort: config.ServicePort);
            await System.WaitForServiceHealthyAsync(port: config.ServicePort, timeout: TimeSpan.FromSeconds(10));

            // Act
            var report = await System.Orchestration.Orchestrator.RunTestAsync(config);

            // Assert
            await Asserting.That(System.Orchestration.Orchestrator)
                .ApiLoadTestWasAborted(report, "consecutive failures");

            Assert.True(report.Results.Phase3Api.ErrorCount > 0,
                "Should have recorded errors");
            Assert.True(report.Results.Phase3Api.DurationSeconds < config.ApiDurationOrDefault.TotalSeconds,
                "Should have terminated early");

            Output.WriteLine($"✓ API test aborted as expected after {report.Results.Phase3Api.DurationSeconds:F2}s");
            Output.WriteLine($"✓ Abort reason: {report.Results.Phase3Api.AbortReason}");
        }
        finally
        {
            await System.ConfigurableReferenceService.DisconnectAsync();
            await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
        }
    }

    [Fact]
    public async Task RunTestAsync_WhenAbortDisabled_ShouldCompleteFullDuration()
    {
        // Arrange
        System.DotNetAotService.Stop();

        System.ConfigurableReferenceService.ConfigureHttpResponse(statusCode: 500);
        System.ConfigurableReferenceService.ConfigurePublication(
            eventCount: 10,
            warmupEventCount: 5);

        var apiDuration = TimeSpan.FromSeconds(5);
        var config = new TestConfigurationBuilder()
            .WithEventCount(10)
            .WithWarmupEventCount(5)
            .WithApiDuration(apiDuration)
            .WithMaxConsecutiveApiFailures(0) // Disabled
            .WithServicePort(9999)

            .Build();

        try
        {
            await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
            await System.ConfigurableReferenceService.ConnectAndSubscribeAsync(listenPort: config.ServicePort);
            await System.WaitForServiceHealthyAsync(port: config.ServicePort, timeout: TimeSpan.FromSeconds(10));

            // Act

            // Assert
            await Asserting.That(System.Orchestration.Orchestrator)
                .ApiLoadTestCompletedWithoutAbort(report);

            await Asserting.That(System.Orchestration.Orchestrator)

            Output.WriteLine($"✓ API test completed full duration: {report.Results.Phase3Api.DurationSeconds:F2}s");
            Output.WriteLine($"✓ Errors recorded: {report.Results.Phase3Api.ErrorCount}");
        }
        finally
        {
            await System.ConfigurableReferenceService.DisconnectAsync();
            await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
        }
    }

    [Fact]
    public async Task RunTestAsync_WithHigherAbortThreshold_ShouldTolerateIntermittentFailures()
    {
        // Arrange
        System.DotNetAotService.Stop();

        System.ConfigurableReferenceService.ConfigureIntermittentFailures(failEveryNthRequest: 3);
        System.ConfigurableReferenceService.ConfigurePublication(
            eventCount: 10,
            warmupEventCount: 5);

        var apiDuration = TimeSpan.FromSeconds(10);
        var config = new TestConfigurationBuilder()
            .WithEventCount(10)
            .WithWarmupEventCount(5)
            .WithApiDuration(apiDuration)
            .WithMaxConsecutiveApiFailures(10) // High tolerance
            .WithServicePort(9999)
            .WithDatabaseName(OrchestrationSystem.IntegrationTestDatabaseName)
            .Build();

        try
        {
            await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
            await System.ConfigurableReferenceService.ConnectAndSubscribeAsync(listenPort: config.ServicePort);
            await System.WaitForServiceHealthyAsync(port: config.ServicePort, timeout: TimeSpan.FromSeconds(10));

            // Act
            var report = await System.Orchestration.Orchestrator.RunTestAsync(config);

            // Assert

            Assert.True(report.Results.Phase3Api.ErrorCount > 0,
```

## Rationale

These tests follow the established patterns in the codebase:
- Use `ConfigurableReferenceService` for controlled failure scenarios (same as `OrchestratorErrorHandlingTests`)
- Use `TestConfigurationBuilder` for fluent configuration
- Use `Asserting.That()` pattern for custom assertions (following project conventions)
- Proper cleanup in `finally` blocks to prevent test pollution
- Queue purging before and after tests

The tests verify:
1. **Core functionality** - Abort detection and reporting works end-to-end
2. **Edge case** - Abort can be disabled when needed
3. **Configuration** - Custom thresholds work correctly
