# Plan: DevContainer System Monitoring Support

## Problem Statement

The `SystemMonitorService` fails in devcontainer environments because:

1. **WSL2 detection is too broad**: `Wsl2Detector.IsWsl2()` returns `true` for ANY Linux environment running on WSL2 kernel
2. **This includes devcontainers**: A Docker container running on Docker Desktop (WSL2 backend) sees the WSL2 kernel
3. **But PowerShell is inaccessible**: Devcontainers don't have `/mnt/c` mounted or PowerShell in PATH
4. **Result**: Tests fail with "No such file or directory" when trying to execute `powershell.exe`

## Environment Matrix

| Environment | Host OS | PowerShell? | `/proc` Available? | Correct Metrics Source |
|-------------|---------|-------------|-------------------|------------------------|
| Windows native | Windows | ✅ Yes | ❌ No | PowerShell → WMI |
| WSL2 direct | Windows | ✅ Yes (`/mnt/c`) | ✅ Yes | PowerShell → WMI |
| Devcontainer on Windows | Windows | ❌ No | ✅ Yes | `/proc` (container view) |
| Devcontainer on macOS | macOS | ❌ No | ✅ Yes | `/proc` (container view) |
| Devcontainer on Linux | Linux | ❌ No | ✅ Yes | `/proc` (container view) |
| Native Linux | Linux | ❌ No | ✅ Yes | `/proc` (host view) |

## Key Insight: Container Metrics Are Correct

For **performance testing**, the right metrics depend on where the service runs:

- **Service in container** → Container metrics show what the service actually experiences
- **Service on host** → Host metrics are relevant

If Docker has `--memory=8g --cpus=4`, the service can only use those resources. Testing should measure the service's reality, not the underlying host.

## Solution: Container-First Detection

### Decision Flow

```
Is running in a container?
  └─ Yes → Use Linux /proc (container's resource view)
  └─ No → Is Windows?
           └─ Yes → Use PowerShell
           └─ No → Is WSL2 with PowerShell accessible?
                    └─ Yes → Use PowerShell (Windows host metrics)
                    └─ No → Use Linux /proc (native Linux)
```

### Detection Methods

**Container Detection:**
1. `/.dockerenv` file exists (Docker)
2. `DEVCONTAINER=true` environment variable (VS Code devcontainers)
3. `/proc/1/cgroup` contains container runtime markers

**PowerShell Accessibility:**
1. Check known paths exist and are executable
2. Validate with simple command execution

### Step 1: Create ContainerDetector.cs

```csharp
namespace PerformanceTester.SystemMonitoring;

/// <summary>
/// Detects if running inside a container (Docker, Podman, Kubernetes, etc.)
/// </summary>
internal static class ContainerDetector
{
    private static readonly Lazy<bool> _isContainer = new(DetectContainer);

    /// <summary>
    /// Gets whether the current process is running inside a container.
    /// </summary>
    public static bool IsContainer => _isContainer.Value;

    private static bool DetectContainer()
    {
        // Method 1: /.dockerenv file (Docker-specific)
        if (File.Exists("/.dockerenv"))
            return true;

        // Method 2: DEVCONTAINER environment variable (VS Code devcontainers)
        if (Environment.GetEnvironmentVariable("DEVCONTAINER")?.Equals("true", StringComparison.OrdinalIgnoreCase) == true)
            return true;

        // Method 3: Check /proc/1/cgroup for container runtime markers
        try
        {
            if (File.Exists("/proc/1/cgroup"))
            {
                var cgroup = File.ReadAllText("/proc/1/cgroup");
                if (cgroup.Contains("docker", StringComparison.OrdinalIgnoreCase) ||
                    cgroup.Contains("containerd", StringComparison.OrdinalIgnoreCase) ||
                    cgroup.Contains("kubepods", StringComparison.OrdinalIgnoreCase) ||
                    cgroup.Contains("lxc", StringComparison.OrdinalIgnoreCase))
                {
                    return true;
                }
            }
        }
        catch
        {
            // Ignore errors reading cgroup
        }

        return false;
    }
}
```

internal static class PowerShellHelper
{
    private static readonly Lazy<string?> _cachedPath = new(FindPowerShellPath);

    /// <summary>
    /// Gets whether PowerShell is available and functional.
    /// </summary>
    public static bool IsAvailable => _cachedPath.Value != null;

    /// <summary>
    /// Gets the path to PowerShell executable.
    /// Throws InvalidOperationException if PowerShell is not available.
    /// </summary>
    public static string GetPowerShellPath() =>

            "PowerShell is not available in this environment.");

### Step 3: Modify SystemMonitorService.cs

Update constructor to use container-first detection:

```csharp
public SystemMonitorService(TimeSpan samplingInterval, ILogger<SystemMonitorService> logger)
{
    // ... existing validation ...

    IsWsl2 = Wsl2Detector.IsWsl2();
    CpuCount = Environment.ProcessorCount;

    // Container-first detection: containers always use /proc
    if (ContainerDetector.IsContainer)
    {
        UseWindowsQueries = false;
        _logger.LogInformation(
            "Container environment detected - using /proc monitoring (container metrics). " +
            "Kernel: {Kernel}", IsWsl2 ? "WSL2" : "Linux");
    }
    else if (OperatingSystem.IsWindows())
    {
        UseWindowsQueries = true;
        _logger.LogInformation("Windows detected - using PowerShell monitoring");
    }
    else if (IsWsl2 && PowerShellHelper.IsAvailable)
    {
        UseWindowsQueries = true;
        var psPath = PowerShellHelper.GetPowerShellPath();
        _logger.LogInformation(
            "WSL2 detected with PowerShell access - using Windows host metrics via {Path}", psPath);
    }
    else
    {
        UseWindowsQueries = false;
        _logger.LogInformation("Native Linux detected - using /proc monitoring");
    }
}
```

### Correct Behavior Per Environment

| Environment | Detection | Monitoring | Metrics Source |
|-------------|-----------|------------|----------------|
| Windows native | `!IsContainer && IsWindows` | Windows | PowerShell → WMI |
| WSL2 direct | `!IsContainer && IsWsl2 && PS available` | Windows | PowerShell → WMI |
| Devcontainer (any host) | `IsContainer` | Linux | /proc/stat, /proc/meminfo |
| Native Linux | `!IsContainer && !IsWindows && !IsWsl2` | Linux | /proc/stat, /proc/meminfo |

## Benefits

1. **Works everywhere** - No conditional mounts or host-specific configuration
2. **Correct metrics** - Container metrics for containerized services, host metrics otherwise
3. **No devcontainer.json changes** - Works with existing configuration
4. **Cross-platform** - Same code works on Windows, macOS, and Linux hosts
5. **Graceful fallback** - Always has a working monitoring path
