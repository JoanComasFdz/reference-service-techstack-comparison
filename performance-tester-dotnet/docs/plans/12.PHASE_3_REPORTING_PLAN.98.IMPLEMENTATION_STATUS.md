## Planned vs Implemented: Detailed Comparison

### ReportGenerator Architecture

**Planned (from 12.PHASE_3_REPORTING_PLAN.3.REPORTGENERATOR_ARCHITECTURE.md):**

```
Input: TestReport + outputDirectory
  ↓
1. Sanitize process name (5-step algorithm)
2. Generate timestamp (yyyyMMdd_HHmmss)
3. Calculate statistics (StatisticsCalculator)
4. Transform data to report models
5. Apply decimal precision rules
6. Format timestamps (main vs samples)
7. Serialize to JSON (snake_case, 2-space indent)
8. Write 7 JSON files
  ↓
Output: 7 JSON files
```

**Implemented:** ❌ NONE

**File Generation Details:**

| File Type | Format | Sampling | Key Fields |
|-----------|--------|----------|-----------|
| Main Report | JSON | N/A | test_date, total_runtime_seconds, phase_timestamps, results |
| Events Throughput | JSON | 100ms | avg_events_per_second, peak, min, std_dev, cv%, response_time |
| API Throughput | JSON | 100ms | avg_calls_per_second, peak, min, std_dev, cv%, response_time |
| Process Resources | JSON | 500ms | cpu_percent, memory_rss_mb, threads |
| System Metrics | JSON | 500ms | cpu_percent, memory_mb |
| RabbitMQ Metrics | JSON | 3000ms | cpu_percent, memory_mb (NO threads) |
| PostgreSQL Metrics | JSON | 3000ms | cpu_percent, memory_mb (NO threads) |

**Critical Implementation Details:**

1. **Process Name Sanitization** (5-step algorithm)
   - Remove file extensions (.jar, .dll, .exe)
   - Replace spaces and special chars with dashes
   - Remove consecutive dashes
   - Remove leading/trailing dashes
   - Convert to lowercase
   - **Example:** `dotnet9AotReferenceService.exe` → `dotnet9aotreferenceservice`

2. **Timestamp Formatting**
   - **Main report:** `yyyy-MM-dd HH:mm:ss` (no timezone)
   - **Sample timestamps:** `yyyy-MM-ddTHH:mm:ss.ffffff+00:00` (ISO 8601 with timezone)

3. **Decimal Precision Rules**
   - Time in seconds: 3 decimals
   - Throughput (per sec): 2 decimals
   - CPU/Memory: 2 decimals
   - Percentages: 1 decimal
   - Response Time (ms): 3 decimals

4. **Zero Handling**
   - **Min calculation:** Excludes zeros (post-test measurements)
   - **Average calculation:** Includes zeros (accurate representation)

5. **Property vs Container Metrics**
   - **Process metrics:** Use `memory_rss_mb`, include `threads` field, 500ms interval
   - **Container metrics:** Use `memory_mb`, NO `threads` field, 3000ms interval

## Critical Success Factors

1. **Exact Format Matching**
   - JSON structure must match Python output exactly
   - snake_case property names (not camelCase)
   - 2-space indentation (not tabs or 4 spaces)
   - Decimal precision must be exact

2. **Statistical Accuracy**
   - Standard deviation must use N-1 (sample formula)
   - Min calculation must exclude zeros
   - Average must include zeros
   - Coefficient of variation must be calculated correctly

3. **Process Name Sanitization**
   - Must follow exact 5-step algorithm
   - Used for all filenames
   - Must be case-insensitive for extensions

4. **Timestamp Formatting**
   - Main report: `yyyy-MM-dd HH:mm:ss` (no timezone)
   - Sample timestamps: `yyyy-MM-ddTHH:mm:ss.ffffff+00:00` (UTC)
   - File naming: `yyyyMMdd_HHmmss`

5. **Cross-Platform Compatibility**
   - Windows and Linux system detection working
   - WSL2 detection and PowerShell queries
   - Path separators handled correctly

6. **Zero Handling Consistency**
   - Min excludes zeros (post-test measurements)
   - Average includes zeros (accurate duration representation)
   - Sampling interval counts all samples

7. **Resource Metric Differentiation**
   - Process metrics: `memory_rss_mb` + `threads` field
   - Container metrics: `memory_mb` (no threads)
   - Different sampling intervals (500ms vs 3000ms)
