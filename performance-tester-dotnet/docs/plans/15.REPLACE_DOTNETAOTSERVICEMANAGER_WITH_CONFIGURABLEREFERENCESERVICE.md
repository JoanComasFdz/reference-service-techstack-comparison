## Overview

### Objective

Remove the `DotNetAotServiceManager` class (which manages an external .NET AOT service process) and replace all its usages with `ConfigurableReferenceService` (an in-process mock service).

### Benefits

| Benefit | Description |
|---------|-------------|
| **Faster tests** | No building/starting external processes (~1-3 minutes saved per test run) |
| **More reliable** | No external process management complexity |
| **More controllable** | Full control over service behavior in tests |
| **Better isolation** | Tests don't depend on external binary state |
| **Simpler CI/CD** | No need to pre-build .NET AOT binary |

### Scope

This change affects only the **Orchestration.IntegrationTests** project. Production code (`PerformanceTester.Orchestration`) remains unchanged.

## Special Considerations

### Process Discovery and Monitoring

**Issue**: `TestOrchestrator.ExecuteSetupPhaseAsync()` calls `IServiceDiscovery.FindServiceProcessIdAsync()` to find a process listening on the port. With `ConfigurableReferenceService`, the HTTP listener runs in the test process itself.

**Behavior after migration**:
- `FindServiceProcessIdAsync()` will find the **test runner process** (e.g., `dotnet` or `testhost`)
- Process monitoring will monitor the **test runner process**
- Resource metrics (CPU, memory) will be for the test process

**Recommendation**: Accept this behavior. The orchestration logic is still tested correctly. For true end-to-end tests with real services, use manual testing or a separate E2E test suite.

### Port Assignments

Each test should use unique ports to prevent conflicts:

| Test File | Test Method | Port |
|-----------|-------------|------|
| `OrchestratorCompleteWorkflowTests` | `RunTestAsync_CompleteWorkflow_*` | 9990 |
| `OrchestratorCancellationTests` | `WhenCancelledDuringEventPhase` | 9994 |
| `OrchestratorCancellationTests` | `WhenCancelledDuringApiPhase` | 9995 |
| `OrchestratorErrorHandlingTests` | `WhenServiceNotRunning` | 9998 |
| `OrchestratorErrorHandlingTests` | `WhenConsumerTimeout` | 9999 |
| `OrchestratorApiAbortTests` | `WhenApiServerReturnsErrors` | 9991 |
| `OrchestratorApiAbortTests` | `WhenAbortDisabled` | 9992 |
| `OrchestratorApiAbortTests` | `WithHigherAbortThreshold` | 9993 |

### Warmup Event Handling

`ConfigurableReferenceService` has a `warmupEventCount` parameter that controls how many events are passed through before the "trigger" event starts the configured publication:

```csharp
// From ConfigurableReferenceService.OnInputEventReceivedAsync():
// - Warmup events (1 through _warmupEventCount): Publish immediately
// - First event AFTER warmup: Triggers configured publication behavior
```

Tests must set `warmupEventCount` to match the test configuration's `WarmupEventCount`.

## Risks and Mitigations

| Risk | Impact | Likelihood | Mitigation |

| Process monitoring shows test process | Low | High | Accept - orchestration logic still tested |
| Port conflicts between parallel tests | Medium | Low | Assign unique ports per test |
| Tests no longer test "real" service | Medium | N/A | Accept tradeoff - tests are for orchestration logic |
| ConfigurableReferenceService doesn't match real service behavior | Medium | Low | ConfigurableReferenceService already mimics real service adequately |
| Warmup event count mismatch | High | Medium | Ensure `warmupEventCount` matches test config |
