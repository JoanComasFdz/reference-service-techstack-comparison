## Overview

The `ComparisonReportGenerator` is the .NET equivalent of Python's `compare_test_results.py` (845 lines). It processes multiple test report JSON files, extracts performance metrics, ranks implementations, awards medals to top performers, and generates comprehensive Markdown comparison tables.

**Input:** Collection of `TestReport` objects (from multiple test runs)

**Output:** Single Markdown file with comparison tables, rankings, and performance highlights

**Core Responsibilities:**
1. Load and validate multiple test reports
2. Extract comparable metrics from each report
3. Rank performers by metric (higher/lower is better)
4. Award medal emojis (🥇🥈🥉) to top 3 distinct values
5. Generate sorted Markdown tables
6. Identify performance highlights
7. Include explanatory notes about variability metrics

## Medal Assignment Algorithm

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Medal Assignment Flow                               │
└─────────────────────────────────────────────────────────────────────────────┘

Input: List of metric values from all test runs
       Sorting strategy (higher/lower is better)

┌────────────────────────────────────────────────────────────────┐
│ Step 1: Sort values according to strategy                      │
│                                                                 │
│ If "higher is better" (throughput, requests):                  │
│   Sort descending: [300.0, 280.0, 260.0, 240.0]               │
│                                                                 │
│ If "lower is better" (CPU%, memory, runtime, CV%):            │
│   Sort ascending: [20.0, 25.0, 30.0, 35.0]                    │
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────────────┐
│ Step 2: Extract top 3 DISTINCT values                         │
│                                                                 │
│ uniqueValues = []                                              │
│ for value in sortedValues:                                     │
│     if value not in uniqueValues:                              │
│         uniqueValues.append(value)                             │
│     if len(uniqueValues) == 3:                                 │
│         break                                                   │
│                                                                 │
│ Result: [300.0, 280.0, 260.0]                                 │
│         (top 3 distinct)                                       │
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────────────┐
│ Step 3: Assign medals to ALL reports with those values        │
│                                                                 │
│ first = uniqueValues[0]   # 300.0                             │
│ second = uniqueValues[1]  # 280.0                             │
│ third = uniqueValues[2]   # 260.0                             │
│                                                                 │
│ for report in allReports:                                      │
│     if report.value == first:                                  │
│         report.medal = "🥇"                                    │
│     elif report.value == second:                               │
│         report.medal = "🥈"                                    │
│     elif report.value == third:                                │
│         report.medal = "🥉"                                    │
│     else:                                                       │
│         report.medal = ""  # No medal                          │
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────────────┐
│ Step 4: Handle ties (multiple reports with same value)        │
│                                                                 │
│ Example with ties:                                             │
│   Input: [300.0, 300.0, 260.0, 240.0]                        │
│                                                                 │
│   Distinct values: [300.0, 260.0, 240.0]                      │
│                                                                 │
│   Medals assigned:                                             │
│   - Both reports with 300.0 get 🥇 (tied for 1st)            │
│   - Report with 260.0 gets 🥈 (2nd distinct value)           │
│   - Report with 240.0 gets 🥉 (3rd distinct value)           │
│                                                                 │
│ NOTE: Ties for same value always get same medal               │
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
```

## Key Design Decisions

### 1. Medal Assignment Based on Distinct Values

**Rationale:** Awards medals to top 3 **distinct values**, not just first 3 entries. This ensures ties are handled correctly.

**Example:**
```
Input: [300.0, 300.0, 280.0, 260.0]  # Two tied for 1st
Distinct: [300.0, 280.0, 260.0]
Medals:
  - Both 300.0 entries get 🥇 (tied for 1st)
  - 280.0 gets 🥈 (2nd distinct value)
  - 260.0 gets 🥉 (3rd distinct value)
```

### 2. Independent Column Ranking

**Rationale:** Each table column is ranked independently. A service can have 🥇 for average and 🥉 for peak.

**Example (Event Throughput):**
```
| Process | Avg      | Peak     | Min      | CV%      |
|---------|----------|----------|----------|----------|
| go      | 254 🥇   | 312 🥈   | 198 🥇   | 4.8 🥇   |
| dotnet  | 248 🥈   | 320 🥇   | 195 🥈   | 5.5 🥈   |
```

### 3. Decimal Precision Rules

**Rationale:** Match Python implementation exactly for fair comparison.

```
Runtime:        2 decimals (123.46)
Throughput:     2 decimals (254.98)
CPU%:           2 decimals (25.50)
Memory (MB):    2 decimals (125.75)
CV%:            1 decimal  (4.8)
Response Time:  3 decimals (0.662)
```

### 4. Sorting Direction Strategy

**Rationale:** Different metrics have different "better" directions.

**Higher is Better:**
- Throughput (events/s, calls/s)
- Total requests
- Min throughput (better worst-case)

**Lower is Better:**
- Runtime (faster is better)
- CPU usage (less overhead)
- Memory usage (smaller footprint)
- CV% (more stable)
- Std Dev (more consistent)
- Response time (faster)

### 5. Explanatory Notes After Tables

**Rationale:** Variability metrics (CV%, Std Dev, Min) need explanation for readers unfamiliar with statistics.

**Required Notes:**
```markdown
*Min (events/s): Lowest throughput recorded during testing. Higher values indicate better worst-case performance.

**Std Dev: Standard deviation measures throughput variability. Lower values indicate more consistent performance.

***CV%: Coefficient of variation (std dev / mean × 100). Lower values indicate more stable relative performance.
```

### 6. Performance Highlights Section

**Rationale:** Quickly identify best performers across all categories without scanning tables.

**Format:**
```markdown
## Performance Highlights

- **Fastest Event Processing:** goReferenceService - 254.98 events/s
- **Fastest API Throughput:** goReferenceService - 1510.70 calls/s
- **Most Stable Event Processing:** goReferenceService - CV: 4.8%
- **Most Stable API Throughput:** goReferenceService - CV: 5.9%
- **Lowest Average CPU Usage:** goReferenceService - 25.50%
- **Lowest Peak Memory Usage:** dotnet9AotReferenceService - 145.23 MB
```

### 7. System Information Context

**Rationale:** Hardware specs essential for interpreting results. Same system can produce different results on different hardware.

**Includes:**
- CPU model and core count
- RAM capacity and speed
- Disk information (filtered >= 500GB)
- OS version
- Test run metadata (start/end time, duration, number of services)

## Summary

The Comparison Report Generator architecture follows a **pipeline pattern**:

1. **Load** → Validate multiple test reports
2. **Extract** → Pull metrics from each report
3. **Rank** → Sort by higher/lower is better strategy
4. **Award** → Assign medals to top 3 distinct values
5. **Generate** → Create sorted Markdown tables
6. **Highlight** → Identify best performers
7. **Write** → Output comprehensive Markdown file

**Key Features:**
- Independent column ranking (medals for each metric)
- Tie handling (same value = same medal)
- Decimal precision matching Python exactly
- Explanatory notes for variability metrics
- Performance highlights for quick insights
- Hardware context for result interpretation

**Python Compatibility:**
- Matches `compare_test_results.py` output format exactly
- Uses `StatisticsCalculator` for all calculations
- Same sorting strategies
- Same medal assignment logic
- Same decimal precision rules
