## Overview

The `ComparisonReportGenerator` is responsible for generating **Markdown comparison reports** that compare multiple test runs side-by-side. This is the .NET equivalent of the Python `compare_test_results.py` script (845 lines).

**Key Responsibilities:**
1. Accept multiple `TestReport` objects as input
2. Sort metrics by "higher is better" or "lower is better"
3. Award medal emojis (🥇🥈🥉) to top 3 performers for each metric
4. Generate comprehensive Markdown tables comparing all test runs
5. Include explanatory notes about variability metrics (CV%, Std Dev)
6. Identify performance highlights (fastest, most stable, lowest resource usage)

**Input:** Collection of `TestReport` objects (from multiple test runs)

**Output:** Markdown file with comprehensive comparison tables

---

## What ComparisonReportGenerator Does

### Core Functionality

The comparison report generator performs the following steps:

1. **Group Test Runs** - Accepts multiple `TestReport` objects representing different test runs
2. **Extract Metrics** - Pulls out key performance metrics from each report:
   - Runtime (total test duration)
   - Event throughput (avg, peak, min, std dev, CV%)
   - API throughput (avg, peak, min, std dev, CV%, response time)
   - CPU usage (avg, peak)
   - Memory usage (avg, peak)
   - System-wide metrics (CPU, memory)
3. **Rank Performers** - For each metric, identify the top 3 performers:
   - **Higher is better:** Throughput, total requests
   - **Lower is better:** Runtime, CPU%, memory, CV%, response time
4. **Award Medals** - Add emoji medals (🥇🥈🥉) to the top 3 values in each metric
5. **Generate Tables** - Create Markdown tables sorted by primary metric:
   - Test Overview (sorted by runtime - lower is better)
   - Event Throughput (sorted by avg throughput - higher is better)
   - API Throughput (sorted by avg throughput - higher is better)
   - CPU Usage (sorted by avg CPU% - lower is better)
   - Memory Usage (sorted by avg memory - lower is better)
   - System Metrics (sorted by avg system CPU% - lower is better)
6. **Add Performance Highlights** - Identify and list:
   - Fastest event processing
   - Fastest API throughput
   - Most stable event processing (lowest CV%)
   - Most stable API throughput (lowest CV%)
   - Lowest average CPU usage
   - Lowest peak memory usage
7. **Include Explanatory Notes** - Add footnotes explaining:
   - Min values (zero filtering for throughput)
   - Standard deviation (variability measure)
   - CV% (coefficient of variation percentage)

### Python Reference Implementation

The Python `compare_test_results.py` provides the reference implementation. Key behaviors to match:

**Medal Assignment (lines 179-230):**
```python

            unique_values.append(val)
        if len(unique_values) == 3:
            break

    return (first, second, third)  # Top 3 distinct values

def add_medal(value_str: str, value: float | None, first, second, third):
    if value == first:
        return f"{value_str} 🥇"
    elif value == second:
        return f"{value_str} 🥈"
    elif value == third:
        return f"{value_str} 🥉"
    else:
        return value_str
```

**Important:** Medals are awarded to the **top 3 distinct values**, not just the first 3 entries. If two test runs have the same value, they both get the same medal.

**Report Structure (lines 251-753):**
1. Header with generation timestamp
2. Test Environment section (hardware, OS, test duration, number of services)
3. Test Runs Overview table (sorted by runtime)
4. Throughput Comparison section:
   - Event Processing Throughput table (sorted by avg)
   - API Throughput table (sorted by avg)
5. Resource Usage Comparison section:
   - Process CPU Usage table (sorted by avg CPU%)
   - Process Memory Usage table (sorted by avg memory)
   - System-Wide Metrics table (sorted by avg system CPU%)
6. Performance Highlights section (bullet list of bests)

## Test Implementation Guide

### Test 1: Medal Emojis for Top 3 Performers

**Test Name:** `GenerateComparisonAsync_ShouldAwardMedalsToTopThree`

**Purpose:** Verify that medal emojis (🥇🥈🥉) are correctly awarded to the top 3 distinct values for each metric.

**Test Steps:**

1. **Arrange:**
   - Create 4 test reports with clear performance hierarchy:
     - goReferenceService: Best in all metrics
     - dotnet9AotReferenceService: Second best
     - rustReferenceService: Third best
     - pythonReferenceService: Fourth (no medal)

2. **Act:**
   - Generate comparison report to temporary file
   - Read generated Markdown content

3. **Assert:**
   - Verify goReferenceService has 🥇 for runtime (in Overview table)
   - Verify dotnet9AotReferenceService has 🥈 for runtime
   - Verify rustReferenceService has 🥉 for runtime
   - Verify pythonReferenceService has no medal for runtime
   - Repeat for event throughput, API throughput, CPU, memory

**Implementation:**

```csharp
[Fact]
public async Task GenerateComparisonAsync_ShouldAwardMedalsToTopThree()
{
    // Arrange
    var reports = new[]
    {
        CreateTestReport("goReferenceService", runtime: 100.0, eventThroughput: 300.0, apiThroughput: 1500.0, avgCpu: 20.0, avgMemory: 100.0),
        CreateTestReport("dotnet9AotReferenceService", runtime: 110.0, eventThroughput: 280.0, apiThroughput: 1450.0, avgCpu: 25.0, avgMemory: 120.0),
        CreateTestReport("rustReferenceService", runtime: 120.0, eventThroughput: 260.0, apiThroughput: 1400.0, avgCpu: 30.0, avgMemory: 140.0),
        CreateTestReport("pythonReferenceService", runtime: 130.0, eventThroughput: 240.0, apiThroughput: 1350.0, avgCpu: 35.0, avgMemory: 160.0)
    };

    var outputPath = Path.Combine(Path.GetTempPath(), $"test-comparison-{Guid.NewGuid()}.md");

    // Act
    await System.ComparisonReportGenerator.GenerateComparisonReportAsync(outputPath, reports);
    var markdown = await File.ReadAllTextAsync(outputPath);

    // Assert - Runtime medals (lower is better)
    await Asserting.That(markdown)
        .ContainsRuntimeMedal("goReferenceService", "🥇")
        .ContainsRuntimeMedal("dotnet9AotReferenceService", "🥈")
        .ContainsRuntimeMedal("rustReferenceService", "🥉")
        .DoesNotContainRuntimeMedal("pythonReferenceService");

    // Assert - Event throughput medals (higher is better)
    await Asserting.That(markdown)
        .ContainsEventThroughputMedal("goReferenceService", "🥇")
        .ContainsEventThroughputMedal("dotnet9AotReferenceService", "🥈")
        .ContainsEventThroughputMedal("rustReferenceService", "🥉")
        .DoesNotContainEventThroughputMedal("pythonReferenceService");

    // Cleanup
    File.Delete(outputPath);
}
```

### Test 2: Higher is Better Sorting

**Test Name:** `GenerateComparisonAsync_ShouldSortByHigherIsBetter`

**Purpose:** Verify that throughput tables are sorted in descending order (highest first) and medals are awarded to highest values.

**Metrics to Test:**
- Event throughput (avg, peak, min)
- API throughput (avg, peak, min)
- Total API requests

**Test Steps:**

1. **Arrange:**
   - Create 3 test reports with varying throughput (random order)
   - Reports NOT pre-sorted

2. **Act:**
   - Generate comparison report
   - Parse Event Throughput table
   - Parse API Throughput table

3. **Assert:**
   - Event throughput table is sorted by avg (descending)
   - First row has highest avg throughput
   - Last row has lowest avg throughput
   - API throughput table is sorted by avg (descending)
   - Medals match sorted order

**Implementation:**

```csharp
[Fact]
```

## Assertion Extensions

### ComparisonReportAssertions

Create custom assertion extensions for validating Markdown content:

```csharp
namespace PerformanceTester.Reporting.IntegrationTests;

/// <summary>
/// Custom assertion extensions for comparison report validation.
/// </summary>
public static class ComparisonReportAssertions
{
    /// <summary>
    /// Asserts that the markdown contains a specific medal for a process in the runtime column.
    /// </summary>
    public static AssertingThat<string> ContainsRuntimeMedal(
        this AssertingThat<string> assertingThat,
        string processName,
        string expectedMedal)
    {
        var markdown = assertingThat.InstanceToAssert;

        // Find Overview table section
        var overviewSection = GetSection(markdown, "## Test Runs Overview");

        // Find row containing process name
        var processRow = overviewSection.Split('\n')
            .FirstOrDefault(line => line.Contains(processName) && line.StartsWith("|"));

        Assert.NotNull(processRow);

        // Extract runtime column (4th column, 0-indexed column 3)
        var columns = processRow.Split('|', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
        Assert.True(columns.Length >= 4, "Overview table should have at least 4 columns");

        var runtimeColumn = columns[3]; // Runtime (s) column

        // Assert medal is present
        Assert.Contains(expectedMedal, runtimeColumn);

        return assertingThat;
    }

    /// <summary>
    /// Asserts that the markdown does NOT contain a medal for a process in the runtime column.
    /// </summary>
    public static AssertingThat<string> DoesNotContainRuntimeMedal(
        this AssertingThat<string> assertingThat,
        string processName)
    {
        var markdown = assertingThat.InstanceToAssert;

        var overviewSection = GetSection(markdown, "## Test Runs Overview");
        var processRow = overviewSection.Split('\n')
            .FirstOrDefault(line => line.Contains(processName) && line.StartsWith("|"));

        Assert.NotNull(processRow);

        var columns = processRow.Split('|', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
        var runtimeColumn = columns[3];

        // Assert NO medals present
        Assert.DoesNotContain("🥇", runtimeColumn);
        Assert.DoesNotContain("🥈", runtimeColumn);
        Assert.DoesNotContain("🥉", runtimeColumn);

        return assertingThat;
    }

    /// <summary>
    /// Asserts that the markdown contains a specific medal for a process in event throughput.
    /// </summary>
    public static AssertingThat<string> ContainsEventThroughputMedal(
        this AssertingThat<string> assertingThat,
        string processName,
        string expectedMedal)
    {
        var markdown = assertingThat.InstanceToAssert;

        var eventSection = GetSection(markdown, "### Event Processing Throughput");
        var processRow = eventSection.Split('\n')
            .FirstOrDefault(line => line.Contains(processName) && line.StartsWith("|"));

        Assert.NotNull(processRow);

        // Extract avg throughput column (3rd column, 0-indexed column 2)
        var columns = processRow.Split('|', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
        Assert.True(columns.Length >= 3, "Event throughput table should have at least 3 columns");

        var avgThroughputColumn = columns[2]; // Avg (events/s) column

        // Assert medal is present
        Assert.Contains(expectedMedal, avgThroughputColumn);

        return assertingThat;
    }

    /// <summary>
    /// Helper: Extracts a section from markdown (from section header to next same-level header).
    /// </summary>
    private static string GetSection(string markdown, string sectionHeader)
    {
        var startIndex = markdown.IndexOf(sectionHeader);
        Assert.True(startIndex >= 0, $"Section '{sectionHeader}' not found in markdown");

        // Determine header level
        var headerLevel = sectionHeader.TakeWhile(c => c == '#').Count();

        // Find next header of same or higher level
        var lines = markdown.Substring(startIndex).Split('\n');
        var sectionLines = new List<string> { lines[0] };

        for (int i = 1; i < lines.Length; i++)
        {
            var line = lines[i];

            // Check if this is a header of same or higher level
            if (line.StartsWith("#"))
            {
                var currentHeaderLevel = line.TakeWhile(c => c == '#').Count();
                if (currentHeaderLevel <= headerLevel)
                    break; // End of section
            }

            sectionLines.Add(line);
        }

        return string.Join('\n', sectionLines);
    }

    /// <summary>
    /// Helper: Extracts a table from a section.
    /// </summary>
    private static string GetTable(string sectionContent, string afterHeader)
    {
        var headerIndex = sectionContent.IndexOf(afterHeader);
        if (headerIndex < 0)
            return string.Empty;

        var afterHeaderContent = sectionContent.Substring(headerIndex);
        var lines = afterHeaderContent.Split('\n');

        // Find first line starting with "|" (table start)
        var tableStart = Array.FindIndex(lines, line => line.Trim().StartsWith("|"));
        if (tableStart < 0)
            return string.Empty;

        // Find last line starting with "|" (table end)
        var tableEnd = tableStart;
        for (int i = tableStart + 1; i < lines.Length; i++)
        {
            if (!lines[i].Trim().StartsWith("|"))
                break;
            tableEnd = i;
        }

        return string.Join('\n', lines.Skip(tableStart).Take(tableEnd - tableStart + 1));
    }

    /// <summary>
    /// Helper: Gets data rows from a table (excludes header and separator).
    /// </summary>
    private static List<string> GetTableRows(string table)
    {
        var lines = table.Split('\n', StringSplitOptions.RemoveEmptyEntries);

        // Skip header (line 0) and separator (line 1)
        return lines.Skip(2).Where(line => line.Trim().StartsWith("|")).ToList();
    }
}
```

## Common Pitfalls to Avoid

### 1. Incorrect Medal Assignment

**Problem:** Assigning medals to first 3 entries instead of top 3 distinct values.

**Wrong:**
```csharp
// Assigns medals to first 3 entries (ignores ties)
for (int i = 0; i < 3 && i < reports.Count; i++)
{
    reports[i].Medal = medals[i]; // ❌ WRONG
}
```

**Correct:**
```csharp
// Find top 3 distinct values
var sortedValues = reports
    .Select(r => r.Throughput)
    .Distinct()
    .OrderByDescending(v => v)
    .Take(3)
    .ToList();

// Assign medals based on value (handles ties)
foreach (var report in reports)
{
    if (report.Throughput == sortedValues[0])
        report.Medal = "🥇"; // ✅ CORRECT
    else if (report.Throughput == sortedValues.ElementAtOrDefault(1))
        report.Medal = "🥈";
    else if (report.Throughput == sortedValues.ElementAtOrDefault(2))
        report.Medal = "🥉";
}
```

### 2. Ignoring Null Values

**Problem:** Including null/zero values in sorting and medal calculations.

**Wrong:**
```csharp
// Includes null values in sorting
var sorted = reports.OrderBy(r => r.Throughput); // ❌ WRONG (nulls first)
```

**Correct:**
```csharp
// Filter out nulls before sorting
var validReports = reports.Where(r => r.Throughput.HasValue);
var sorted = validReports.OrderByDescending(r => r.Throughput.Value); // ✅ CORRECT
```

### 3. Incorrect Decimal Precision

**Problem:** Not applying correct rounding per specification.

**Wrong:**
```csharp
// No rounding or incorrect precision
$"{runtime}"; // ❌ WRONG (could be 123.456789)
$"{runtime:F5}"; // ❌ WRONG (5 decimals, spec says 2)
```

**Correct:**
```csharp
// Apply correct precision per spec
$"{Math.Round(runtime, 2):F2}"; // ✅ CORRECT (123.46)
$"{Math.Round(throughput, 2):F2}"; // ✅ CORRECT (254.98)
$"{Math.Round(cvPercent, 1):F1}"; // ✅ CORRECT (4.8)
$"{Math.Round(responseTime, 3):F3}"; // ✅ CORRECT (0.662)
```

### 4. Inconsistent Sorting Direction

**Problem:** Mixing up "higher is better" vs "lower is better" sorting.

**Remember:**
- **Higher is better:** Throughput, requests, min throughput
  - Sort: `OrderByDescending` (highest first)
  - Medals: Highest value gets 🥇
- **Lower is better:** Runtime, CPU%, memory, CV%, std dev, response time
  - Sort: `OrderBy` (lowest first)
  - Medals: Lowest value gets 🥇

### 5. Missing Notes/Footnotes

**Problem:** Forgetting to include explanatory notes after tables.

**Required after throughput tables:**
```markdown
*Min (events/s): Lowest throughput recorded during testing. Higher values indicate better worst-case performance.

**Std Dev: Standard deviation measures throughput variability. Lower values indicate more consistent performance.

***CV%: Coefficient of variation (std dev / mean × 100). Lower values indicate more stable relative performance.
```

### 6. Incorrect Table Format

**Problem:** Malformed Markdown tables (missing pipes, wrong column count).

**Wrong:**
```markdown
| # | Process | Value
|---|---------|------|
| 1 | Service | 100.00 |  ❌ WRONG (missing pipe at end of header)
```

**Correct:**
```markdown
| # | Process | Value |
|---|---------|-------|
| 1 | Service | 100.00 |  ✅ CORRECT
```

### 7. Not Using StatisticsCalculator

**Problem:** Manually calculating statistics instead of using `StatisticsCalculator`.

**Wrong:**
```csharp
// Manual calculation (may not match Python)
var avg = values.Average(); // ❌ WRONG (no rounding)
var stdDev = /* manual formula */; // ❌ WRONG (may use N instead of N-1)
```

**Correct:**
```csharp
// Use StatisticsCalculator (matches Python exactly)
var avg = StatisticsCalculator.CalculateAverage(values); // ✅ CORRECT
var stdDev = StatisticsCalculator.CalculateStandardDeviation(values); // ✅ CORRECT (uses N-1)
var cv = StatisticsCalculator.CalculateCoefficientOfVariation(values); // ✅ CORRECT
```
