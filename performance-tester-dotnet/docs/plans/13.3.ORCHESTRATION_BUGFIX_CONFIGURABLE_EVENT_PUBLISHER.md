## Overview

**Issue:** EventConsumerService is consuming from the wrong routing key, preventing correct integration testing of timeout scenarios.

**Discovery:** When attempting to test orchestrator timeout behavior, we discovered that EventConsumerService consumes from `instrument.status.changed` instead of `instrumentstatus.kpi.updated`, breaking the correct message flow.

**Resolution:**
1. Fix EventConsumerService routing key
2. Rename TestEventPublisher → ConfigurableReferenceService
3. Enhance ConfigurableReferenceService to act as a bi-directional mock service
4. Update integration test to use full orchestrator workflow

---

## Bug Identification

### Current (Incorrect) Message Flow

```
Orchestrator EventPublisher
  └─► "instrument.status.changed" (routing key)
        └─► DotNetAoT Service (should consume, but NOT tested)
        └─► Orchestrator EventConsumer ❌ WRONG! Consuming same events it publishes!
```

**Problem:** EventConsumerService and EventPublisher both use the same routing key:

```csharp
// EventPublishing/RabbitMqPublisher.cs
private const string RoutingKey = "instrument.status.changed"; // ✅ CORRECT

// EventConsuming/EventConsumerService.cs
private const string RoutingKey = "instrument.status.changed"; // ❌ WRONG!
```

### Expected (Correct) Message Flow

According to parent `/workspace/CLAUDE.md`:

```
Orchestrator EventPublisher
  └─► "instrument.status.changed"
        └─► DotNetAoT Service consumes
              └─► Processes + persists to PostgreSQL
                    └─► Publishes "instrumentstatus.kpi.updated"
                          └─► Orchestrator EventConsumer ✅ CORRECT
```

**Services should:**
- Consume events from RabbitMQ (`instrument.status.changed`)
- Persist data to PostgreSQL (dedicated database per service)
- Publish processed events back to RabbitMQ (`instrumentstatus.kpi.updated`)
- Expose HTTP API endpoint: `GET /kpi` (returns latest record)

## Root Cause Analysis

### Why This Bug Exists

1. **Phase 2 EventConsuming was developed before Orchestration Phase 4**
2. **No real service integration testing initially** - tests used mocked publishers
3. **EventConsumerService was designed for generic consumption** without service-specific context
4. **Copy-paste from EventPublishing** - routing key was duplicated

### Why It Wasn't Caught Earlier

1. **Integration tests didn't use real .NET AOT service**
2. **EventConsuming tests used direct publisher (same routing key)**
3. **Orchestration tests started service but used fast publishing (timeout never triggered)**

### Impact

**Production Code:**
- ❌ Orchestrator cannot test real services correctly
- ❌ EventConsumer receives wrong events (publisher's output, not service's output)
- ❌ Tests pass but don't validate actual integration

**Integration Tests:**
- ❌ Timeout tests cannot trigger properly (service too fast)
- ❌ No way to test slow/stalled service scenarios
- ❌ Cannot test partial completion (e.g., 100/1000 events received)

### Part 2: Rename and Enhance TestEventPublisher

#### Rename: TestEventPublisher → ConfigurableReferenceService

**Reason:** The name "ConfigurableReferenceService" better describes its dual role:
1. **Consumer** - Subscribes to input events (`instrument.status.changed`)
2. **Publisher** - Publishes output events at controlled rate (`instrumentstatus.kpi.updated`)

#### New Architecture

**ConfigurableReferenceService** acts as a **mock service** for integration testing:

```
┌─────────────────────────────────────────────────────────┐
│         ConfigurableReferenceService                      │
│         (Mock Service for Testing)                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────────┐          ┌──────────────┐           │
│  │   Consumer   │          │  Publisher   │           │
│  │              │          │              │           │
│  │  Subscribes  │  Trigger │  Publishes   │           │
│  │  to input    │  ───────►│  to output   │           │
│  │  events      │          │  events      │           │
│  └──────────────┘          └──────────────┘           │
│         │                          │                   │
└─────────┼──────────────────────────┼───────────────────┘
          │                          │
          │                          │
          ▼                          ▼
    "instrument.status        "instrumentstatus.kpi
     .changed"                 .updated"
    (INPUT)                    (OUTPUT)
```

**Behavior:**

1. **Initialization:**
   - Connects to RabbitMQ
   - Subscribes to `instrument.status.changed` (input events)
   - Waits for trigger

2. **Trigger:**
   - Receives 1st event from `instrument.status.changed`
   - **IGNORES content** (just uses it as signal to start)

3. **Publication:**
   - Publishes N events to `instrumentstatus.kpi.updated`
   - With configurable delay between events (default: 0s = as fast as possible)
   - For timeout tests: publishes 1 event, then stops (triggers timeout)

4. **Cleanup:**
   - Continues consuming input events (ignores them)
   - Disconnects on disposal

#### Public API

```csharp
public sealed class ConfigurableReferenceService : IAsyncDisposable
{
    /// <summary>
    /// Connects to RabbitMQ and subscribes to input events.
    /// Waits for first event as trigger.
    /// </summary>
    Task ConnectAndSubscribeAsync(CancellationToken cancellationToken = default);

    /// <summary>
    /// Configures the publication behavior (called before connecting).
    /// </summary>
    /// <param name="eventCount">Number of KPI events to publish after trigger</param>
    /// <param name="delayBetweenEvents">Delay between events (default: 0 = fast)</param>
    void ConfigurePublication(int eventCount, TimeSpan? delayBetweenEvents = null);

    /// <summary>
    /// Disconnects from RabbitMQ.
    /// </summary>
    Task DisconnectAsync(CancellationToken cancellationToken = default);
}
```

#### Internal State Machine

```
┌─────────────┐
│   Created   │
└──────┬──────┘
       │ ConnectAndSubscribeAsync()
       ▼
┌─────────────┐
│  Listening  │───► Waiting for 1st event from input queue
└──────┬──────┘
       │ 1st event received
       ▼
┌─────────────┐
│  Triggered  │───► Start publishing N events to output queue
└──────┬──────┘
       │ All N events published (or error)
       ▼
┌─────────────┐
│  Completed  │───► Still consuming (ignoring) input events
└──────┬──────┘
       │ DisconnectAsync()
       ▼
┌─────────────┐
│ Disconnected│
└─────────────┘
```

#### Implementation Details

**Input Consumer (new):**

```csharp
private async Task OnInputEventReceivedAsync(object sender, BasicDeliverEventArgs eventArgs)
{
    try
    {
        // Increment input counter
        var inputCount = Interlocked.Increment(ref _receivedInputEventCount);

        // First event triggers publication
        if (inputCount == 1)
        {
            _output?.WriteLine($"✓ ConfigurableReferenceService received trigger event (ID: {eventArgs.DeliveryTag})");
            _triggerCompletionSource?.TrySetResult(true);

            // Start publishing output events
            _ = Task.Run(async () => await PublishOutputEventsAsync(), _cancellationTokenSource.Token);
        }
        else
        {
            // Ignore subsequent input events (just ACK them)
            _output?.WriteLine($"  ⊙ Ignoring input event {inputCount} (already triggered)");
        }

        // Always ACK input events
        if (_inputChannel != null)
        {
            await _inputChannel.BasicAckAsync(deliveryTag: eventArgs.DeliveryTag, multiple: false);
        }
    }
    catch (Exception ex)
    {
        _output?.WriteLine($"❌ Error processing input event: {ex.Message}");

        // NACK and requeue
        if (_inputChannel != null)
        {
            await _inputChannel.BasicNackAsync(
                deliveryTag: eventArgs.DeliveryTag,
                multiple: false,
                requeue: true);
        }
    }
}
```

**Output Publisher (enhanced from existing):**

```csharp
private async Task PublishOutputEventsAsync()
{
    try
    {
        _output?.WriteLine(
            $"ConfigurableReferenceService publishing {_configuredEventCount} KPI event(s) " +
            $"with {_delayBetweenEvents.TotalSeconds:F2}s delay...");

        for (int i = 0; i < _configuredEventCount; i++)
        {
            _cancellationTokenSource.Token.ThrowIfCancellationRequested();

            // Create KPI CloudEvent using shared library
            var cloudEvent = CreateKpiEvent(eventNumber: i + 1);

            // Serialize and publish
            var messageBytes = _formatter.EncodeStructuredModeMessage(cloudEvent, out var contentType);
            var properties = new BasicProperties
            {
                ContentType = contentType.ToString(),
                DeliveryMode = DeliveryModes.Persistent
            };

            await _outputChannel!.BasicPublishAsync(
                exchange: ExchangeName,
                routingKey: OutputRoutingKey,  // "instrumentstatus.kpi.updated"
                mandatory: false,
                basicProperties: properties,
                body: messageBytes.ToArray(),
                cancellationToken: _cancellationTokenSource.Token);

            _output?.WriteLine($"  ✓ Published KPI event {i + 1}/{_configuredEventCount} (ID: {cloudEvent.Id})");

            // Delay before next event (except last one)
            if (i < _configuredEventCount - 1 && _delayBetweenEvents > TimeSpan.Zero)
            {
                await Task.Delay(_delayBetweenEvents, _cancellationTokenSource.Token);
            }
        }

        _output?.WriteLine($"✓ ConfigurableReferenceService published {_configuredEventCount} KPI event(s)");
        _publicationCompletionSource?.TrySetResult(true);
    }
    catch (Exception ex)
    {
        _output?.WriteLine($"❌ Publication failed: {ex.Message}");
        _publicationCompletionSource?.TrySetException(ex);
    }
}
```

**File:** `src/PerformanceTester.Orchestration.IntegrationTests/OrchestratorErrorHandlingTests.cs`

**New Implementation:**

```csharp
[Fact]
public async Task RunTestAsync_WhenConsumerTimeout_ShouldIncludeReceivedCount()
{
    // Arrange
    // DON'T start the .NET AOT service
    // ConfigurableReferenceService will act as a slow mock service

    // Configure mock service to publish only 1 KPI event (out of 1000 expected)
    System.ConfigurableReferenceService.ConfigurePublication(
        eventCount: 1,              // Publish only 1 event
        delayBetweenEvents: null);  // Immediately (no delay)

    // Connect mock service (starts listening for input events)
    await System.ConfigurableReferenceService.ConnectAndSubscribeAsync();

    var config = new TestConfigurationBuilder()
        .WithEventCount(1000)  // Orchestrator will publish 1000 input events
        .WithInactivityTimeout(TimeSpan.FromSeconds(1))  // 1s timeout
        .WithDatabaseName(OrchestrationSystem.IntegrationTestDatabaseName)
        .Build();

    // Act & Assert
    await Asserting.That(System.Orchestration.Orchestrator)
        .ThrowsConsumerInactivityTimeout(
            config: config,
            expectedReceivedCount: 1);  // Should receive 1 before timeout

    // Timeline:
    // t=0s   → ConfigurableReferenceService listening for input events
    // t=0s   → Orchestrator starts, publishes 1000 input events (fast)
    // t=0s   → Mock service receives 1st input event → triggers
    // t=0s   → Mock service publishes 1 KPI event → stops
    // t=0-1s → Orchestrator EventConsumer receives 1 KPI event, waits for more
    // t=1s   → Orchestrator timeout fires! ✅
}
```

**Assertion Extension Implementation:**

Add to existing `src/PerformanceTester.Orchestration.IntegrationTests/Infrastructure/OrchestrationAssertions.cs`:

```csharp
/// <summary>
/// Asserts that the orchestrator throws TimeoutException due to consumer inactivity timeout.
/// Verifies the exception message includes the expected progress (received count).
/// </summary>
/// <param name="assertingThat">The asserting wrapper</param>
/// <param name="config">Test configuration</param>
/// <param name="expectedReceivedCount">Expected number of events received before timeout</param>
public static async Task ThrowsConsumerInactivityTimeout(
    this AssertingThat<ITestOrchestrator> assertingThat,
    TestConfiguration config,
    int expectedReceivedCount)
{
    var exception = await Assert.ThrowsAsync<TimeoutException>(async () =>
    {
        await assertingThat.InstanceToAssert.RunTestAsync(config);
    });

    // Verify exception message includes timeout reason and progress
    Assert.Contains("Inactivity timeout", exception.Message);
    Assert.Contains($"{expectedReceivedCount}/{config.EventCount}", exception.Message);
}
```

**Why This Works:**

1. **Orchestrator publishes 1000 input events** → Fast (100s-1000s events/sec)
2. **Mock service consumes 1st input event** → Triggers publication
3. **Mock service publishes 1 KPI event** → Then stops
4. **Orchestrator EventConsumer receives 1 KPI event** → Waits for more
5. **No more KPI events for 1 second** → Inactivity timeout fires ✅

**Key Insight:** The orchestrator's input publishing speed doesn't matter. What matters is the mock service's output publishing rate (controlled, slow).
