## OrchestrationSystem Class

### Purpose

Provides access to:

1. **Production Orchestrator** - ITestOrchestrator
2. **Test Fixture Service** - .NET 9 AOT implementation manager
3. **ConfigurableReferenceService** - Bi-directional mock service for timeout testing
4. **Infrastructure Helpers** - PostgreSQL, RabbitMQ (inherited from base System)

### Implementation

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Npgsql;
using PerformanceTester.IntegrationTesting;
using Xunit.Abstractions;

namespace PerformanceTester.Orchestration.IntegrationTests.Infrastructure;

/// <summary>
/// System under test for Orchestration integration tests.
/// Provides access to:
/// - ITestOrchestrator (production API)
/// - DotNetAotServiceManager (test fixture)
/// - ConfigurableReferenceService (bi-directional mock service for testing)
/// - Infrastructure helpers (PostgreSQL, RabbitMQ)
/// </summary>
public sealed class OrchestrationSystem : IntegrationTesting.System
{
    /// <summary>
    /// Database name used by all orchestration integration tests.
    /// Isolated from production database (dotnet9aot_db) to prevent test data pollution.
    /// </summary>
    public const string IntegrationTestDatabaseName = "dotnet9aot_perftest_integrationtest_db";

    public Orchestration Orchestration { get; private set; } = null!;
    public DotNetAotServiceManager DotNetAotService { get; private set; } = null!;
    public ConfigurableReferenceService ConfigurableReferenceService { get; private set; } = null!;

    protected override async Task InitializeSystemAsync()
    {
        Output?.WriteLine("[INIT] Starting OrchestrationSystem initialization...");
        await base.InitializeSystemAsync();

        // CRITICAL: Close all lingering RabbitMQ connections from previous tests
        await base.RabbitMQ.CloseAllConnectionsAsync();

        // Create integration test database (idempotent)
        try
        {
            await base.PostgreSQL.CreateTestDatabaseAsync(IntegrationTestDatabaseName);
        }
        catch (PostgresException ex) when (ex.SqlState == "42P04")
        {
            // Database already exists - ignore
        }

        // Parse connection strings for DotNetAotServiceManager
        var pgBuilder = new NpgsqlConnectionStringBuilder(base.PostgreSQL.ConnectionString);
        var rabbitMqUri = new Uri(base.RabbitMQ.ConnectionString);
        var rabbitMqCredentials = rabbitMqUri.UserInfo.Split(':');

        // Initialize .NET AOT service manager with dynamic connection details
        this.DotNetAotService = new DotNetAotServiceManager(
            postgresHost: pgBuilder.Host!,
            postgresPort: pgBuilder.Port,
            postgresUser: pgBuilder.Username!,
            postgresPassword: pgBuilder.Password!,
            rabbitMqHost: rabbitMqUri.Host,
            rabbitMqPort: rabbitMqUri.Port,
            rabbitMqUser: rabbitMqCredentials[0],
            rabbitMqPassword: rabbitMqCredentials[1],
            output: base.Output);

        // Initialize orchestration facade (creates IHost with all services)
        this.Orchestration = new Orchestration(
            postgresConnectionString: base.PostgreSQL.ConnectionString,
            rabbitMqConnectionString: base.RabbitMQ.ConnectionString,
            rabbitMqContainerName: "performance-tester-rabbitmq",
            postgresContainerName: "performance-tester-postgres",
            output: base.Output);

        // Initialize configurable reference service (fresh instance per test)
        this.ConfigurableReferenceService = new ConfigurableReferenceService(
            connectionString: base.RabbitMQ.ConnectionString,
            output: base.Output);

        Output?.WriteLine("[INIT] ✅ OrchestrationSystem initialization complete");
    }

    /// <summary>
    /// Waits for the ConfigurableReferenceService to be fully ready via health check.
    /// </summary>
    public async Task WaitForServiceHealthyAsync(int port, TimeSpan? timeout = null)
    {
        var actualTimeout = timeout ?? TimeSpan.FromSeconds(10);
        var healthUrl = $"http://localhost:{port}/health";

        using var httpClient = new HttpClient { Timeout = TimeSpan.FromSeconds(2) };
        var startTime = DateTime.UtcNow;

        while (DateTime.UtcNow - startTime < actualTimeout)
        {
            try
            {
                var response = await httpClient.GetAsync(healthUrl);
                if (response.IsSuccessStatusCode) return;
            }
            catch { /* Service not ready */ }
            await Task.Delay(200);
        }

        throw new TimeoutException($"Service health check at {healthUrl} did not return ready within {actualTimeout.TotalSeconds}s");
    }

    public override void Dispose()
    {
        DotNetAotService?.Dispose();
        ConfigurableReferenceService?.DisposeAsync().AsTask().GetAwaiter().GetResult();
        Orchestration?.Dispose();
        base.Dispose();
    }
}
```

**Key Changes from Original Plan:**
- ✅ **Async initialization** - `InitializeSystemAsync()` instead of `InitializeSystem()`
- ✅ **Database creation** - Creates integration test database automatically
- ✅ **Connection cleanup** - Closes lingering RabbitMQ connections
- ✅ **Dynamic connection strings** - Parses testcontainer connection strings for DotNetAotService
- ✅ **ConfigurableReferenceService** - Added for timeout scenario testing
- ✅ **Health check method** - `WaitForServiceHealthyAsync()` for deterministic service readiness

## Orchestration Facade

### Purpose

Encapsulates IHost creation and service resolution for orchestrator.

### Implementation

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Xunit.Abstractions;

namespace PerformanceTester.Orchestration.IntegrationTests.Infrastructure;

/// <summary>
/// Facade for accessing ITestOrchestrator and dependencies.
/// Creates IHost with all Phase 1-4 services registered via AddOrchestration().
/// </summary>
public sealed class Orchestration : IDisposable
{
    private IHost? _host;
    private readonly ITestOutputHelper? _output;

    public ITestOrchestrator Orchestrator { get; private set; } = null!;

    public Orchestration(
        string postgresConnectionString,
        string rabbitMqConnectionString,
        string rabbitMqContainerName,
        string postgresContainerName,
        ITestOutputHelper? output)
    {
        _output = output;

        // Build IHost with all services
        var builder = Host.CreateApplicationBuilder();

        // Configure logging to test output
        builder.Logging.ClearProviders();
        if (output != null)
        {
            builder.Logging.AddXunitOutput(output);
        }

        // Single call registers ALL dependencies (Phases 1-4)
        builder.Services.AddOrchestration(
            postgresConnectionString: postgresConnectionString,
            rabbitMqConnectionString: rabbitMqConnectionString,
            rabbitMqContainerName: rabbitMqContainerName,
            postgresContainerName: postgresContainerName);

        _host = builder.Build();

        // Resolve orchestrator
        this.Orchestrator = _host.Services.GetRequiredService<ITestOrchestrator>();
    }

    public void Dispose()
    {
        _host?.Dispose();
    }
}
```

**Key Design Decisions:**

- ✅ Uses production `AddOrchestration()` extension method (single entry point)
- ✅ All dependencies registered internally by AddOrchestration()
- ✅ Logging configured to capture test output
- ✅ Follows VSA principle: each slice owns its DI registration

## DotNetAotServiceManager

### Purpose

Manages .NET 9 AOT service lifecycle for integration tests:

1. Builds .NET AOT service (if needed)
2. Starts service on port 8093
3. Waits for health check
4. Stops service on disposal

### Implementation

```csharp
using System.Diagnostics;
using Xunit.Abstractions;

namespace PerformanceTester.Orchestration.IntegrationTests.Infrastructure;

/// <summary>
/// Manages .NET 9 AOT service lifecycle for integration tests.
/// Builds, starts, and stops the .NET AOT reference service.
/// </summary>
public sealed class DotNetAotServiceManager : IDisposable
{
    private readonly ITestOutputHelper? _output;
    private Process? _dotnetProcess;
    private const string DotNetAotServicePath = "/workspace/implementations/dotnet9aot";
    private const string DotNetAotServiceBinary = "dotnet9AotReferenceService";
    private const string DotNetAotServicePublishPath = "bin/Release/net9.0/linux-x64/publish";
    private const int DotNetAotServicePort = 8093;
    private const string DotNetAotServiceUrl = "http://localhost:8093";

    public DotNetAotServiceManager(ITestOutputHelper? output)
    {
        _output = output;
    }

    /// <summary>
    /// Builds the .NET AOT service if the binary doesn't exist.
    /// </summary>
    public void BuildIfNeeded()
    {
        var binaryPath = Path.Combine(DotNetAotServicePath, DotNetAotServicePublishPath, DotNetAotServiceBinary);

        if (File.Exists(binaryPath))
        {
            _output?.WriteLine($".NET AOT service binary already exists: {binaryPath}");
            return;
        }

        _output?.WriteLine("Building .NET AOT service (this may take 1-3 minutes)...");

        var buildProcess = new Process
        {
            StartInfo = new ProcessStartInfo
            {
                FileName = "dotnet",
                Arguments = "publish -c Release",
                WorkingDirectory = DotNetAotServicePath,
                RedirectStandardOutput = true,
                RedirectStandardError = true,
                UseShellExecute = false
            }
        };

        buildProcess.Start();
        var output = buildProcess.StandardOutput.ReadToEnd();
        var error = buildProcess.StandardError.ReadToEnd();
        buildProcess.WaitForExit();

        if (buildProcess.ExitCode != 0)
        {
            throw new InvalidOperationException(
                $".NET AOT service build failed with exit code {buildProcess.ExitCode}. " +
                $"Error: {error}");
        }

        _output?.WriteLine(".NET AOT service built successfully");
    }

    /// <summary>
    /// Starts the .NET AOT service and waits for it to be healthy.
    /// </summary>
    public async Task StartAsync(string databaseName, CancellationToken cancellationToken = default)
    {
        // Ensure binary exists
        BuildIfNeeded();

        var binaryPath = Path.Combine(DotNetAotServicePath, DotNetAotServicePublishPath, DotNetAotServiceBinary);

        _output?.WriteLine($"Starting .NET AOT service from {binaryPath}...");

        _dotnetProcess = new Process
        {
            StartInfo = new ProcessStartInfo
            {
                FileName = binaryPath,
                WorkingDirectory = Path.Combine(DotNetAotServicePath, DotNetAotServicePublishPath),
                RedirectStandardOutput = true,
                RedirectStandardError = true,
                UseShellExecute = false,
                // Environment variables for .NET AOT service
                // Using ASP.NET Core hierarchical configuration format (double-underscore)
                EnvironmentVariables =
                {
                    ["Postgres__Host"] = "localhost",
                    ["Postgres__Port"] = "5432",
                    ["Postgres__Database"] = databaseName,
                    ["Postgres__Username"] = "admin",
                    ["Postgres__Password"] = "admin",
                    ["RabbitMQ__Host"] = "localhost",
                    ["RabbitMQ__Port"] = "5672",
                    ["RabbitMQ__Username"] = "admin",
                    ["RabbitMQ__Password"] = "admin",
                    ["ASPNETCORE_URLS"] = DotNetAotServiceUrl
                }
            }
        };

        // Capture output for debugging
        _dotnetProcess.OutputDataReceived += (sender, e) =>
        {
            if (!string.IsNullOrEmpty(e.Data))
                _output?.WriteLine($"[.NET AOT Service] {e.Data}");
        };
        _dotnetProcess.ErrorDataReceived += (sender, e) =>
        {
            if (!string.IsNullOrEmpty(e.Data))
                _output?.WriteLine($"[.NET AOT Service ERROR] {e.Data}");
        };

        _dotnetProcess.Start();
        _dotnetProcess.BeginOutputReadLine();
        _dotnetProcess.BeginErrorReadLine();

        // Wait for service to be healthy
        await WaitForHealthAsync(cancellationToken);

        _output?.WriteLine($".NET AOT service started successfully on {DotNetAotServiceUrl}");
    }

    /// <summary>
    /// Waits for the .NET AOT service to respond to health checks.
    /// </summary>
    private async Task WaitForHealthAsync(CancellationToken cancellationToken)
    {
        using var httpClient = new HttpClient();
        var timeout = TimeSpan.FromSeconds(30);
        var stopwatch = Stopwatch.StartNew();

        while (stopwatch.Elapsed < timeout)
        {
            try
            {
                var response = await httpClient.GetAsync(
                    $"{DotNetAotServiceUrl}/kpi",
                    cancellationToken);

                if (response.IsSuccessStatusCode)
                {
                    _output?.WriteLine($".NET AOT service healthy after {stopwatch.Elapsed.TotalSeconds:F2}s");
                    return;
                }
            }
            catch
            {
                // Service not ready yet, continue polling
            }

            await Task.Delay(500, cancellationToken);
        }

        throw new TimeoutException(
            $".NET AOT service did not become healthy within {timeout.TotalSeconds}s");
    }

    /// <summary>
    /// Stops the .NET AOT service.
    /// </summary>
    public void Stop()
    {
        if (_dotnetProcess == null || _dotnetProcess.HasExited)
            return;

        _output?.WriteLine("Stopping .NET AOT service...");

        try
        {
            _dotnetProcess.Kill(entireProcessTree: true);
            _dotnetProcess.WaitForExit(5000);
            _output?.WriteLine(".NET AOT service stopped");
        }
        catch (Exception ex)
        {
            _output?.WriteLine($"Error stopping .NET AOT service: {ex.Message}");
        }
    }

    public void Dispose()
    {
        Stop();
        _dotnetProcess?.Dispose();
    }
}
```

**Key Features:**

- ✅ Builds .NET AOT service if binary doesn't exist
- ✅ Configures environment variables (ASP.NET Core hierarchical format: `Postgres__Database`, `RabbitMQ__Host`, etc.)
- ✅ Accepts database name as parameter (configurable per test)
- ✅ Captures stdout/stderr for debugging
- ✅ Health check polling with timeout
- ✅ Graceful shutdown on disposal
- ✅ Native binary execution (no runtime required)

### 1. Complete Workflow Test

**File:** `OrchestratorCompleteWorkflowTests.cs`

```csharp
using Xunit;
using Xunit.Abstractions;
using PerformanceTester.Orchestration.IntegrationTests.Infrastructure;

namespace PerformanceTester.Orchestration.IntegrationTests;

public sealed class OrchestratorCompleteWorkflowTests(ITestOutputHelper output)
    : IntegrationTest(output)
{
    /// <summary>
    /// Comprehensive integration test that verifies the entire orchestration workflow
    /// from service discovery through all test phases to final report generation.
    /// This test consolidates all happy-path scenarios with phase-by-phase assertions.
    /// </summary>
    [Fact]
    public async Task RunTestAsync_CompleteWorkflow_ShouldExecuteAllPhasesSuccessfully()
    {
        // ====================================================================
        // ARRANGE
        // ====================================================================

        // Start .NET AOT service
        await System.DotNetAotService.StartAsync(System.IntegrationTestDatabaseName);

        // Create unique results folder for this test run
        var resultsFolder = $"./test-results-{Guid.NewGuid():N}";

        var config = new TestConfigurationBuilder()
            .WithEventCount(500)                    // Sufficient for meaningful throughput
            .WithApiWorkers(1)
            .WithResultsFolder(resultsFolder)
            .Build();

        // ====================================================================
        // ACT
        // ====================================================================

        var report = await System.Orchestration.Orchestrator.RunTestAsync(config);

        // ====================================================================
        // ASSERT - PHASE 0: SETUP (Service Discovery)
        // ====================================================================

        // Verify service was discovered
        Assert.True(report.MonitoredProcess.Pid > 0,
            "Service PID should be discovered");
        Assert.Equal("dotnet9AotReferenceService", report.MonitoredProcess.Name);

        Output.WriteLine($"✓ Phase 0 (Setup): Service discovered (PID: {report.MonitoredProcess.Pid})");

        // ====================================================================
        // ASSERT - PHASE 0.5: WARMUP
        // ====================================================================

        // Warmup runs successfully (no exception thrown)
        // Warmup data is discarded, so no direct assertions on warmup metrics
        // Success indicated by reaching event test phase
        Assert.True(report.Results.Phase1Publish.DurationSeconds > 0,
            "Event publish phase should have run (indicates warmup completed)");

        Output.WriteLine("✓ Phase 0.5 (Warmup): Completed successfully (data discarded)");

        // ====================================================================
        // ASSERT - PHASE 1 & 2: EVENT TEST (Publish + Consume)
        // ====================================================================

        // Verify event count configuration
        Assert.Equal(500, report.Configuration.NumEvents);

        // Verify publishing phase completed
        Assert.True(report.Results.Phase1Publish.DurationSeconds > 0,
            "Event publish phase should have duration");
        Assert.True(report.Results.Phase1Publish.ThroughputEventsPerSec > 0,
            "Event publish throughput should be positive");

        // Verify consuming phase completed
        Assert.True(report.Results.Phase2Consume.DurationSeconds > 0,
            "Event consume phase should have duration");
        Assert.True(report.Results.Phase2Consume.ThroughputEventsPerSec > 0,
            "Event consume throughput should be positive");

        // Verify concurrent execution (Phase2 starts before Phase1 ends)
        Assert.True(report.PhaseTimestamps.Phase2Start < report.PhaseTimestamps.Phase1End,
            "Consumer should start before publisher completes (concurrent execution)");

        // Verify publishing completes faster than consuming (expected behavior)
        Assert.True(report.Results.Phase1Publish.DurationSeconds < report.Results.Phase2Consume.DurationSeconds,
            "Publishing should complete faster than consuming");

        // Verify throughput samples collected
        Assert.NotEmpty(report.EventsThroughputSamples);

        // Verify samples have valid timestamps
        var eventSamples = report.EventsThroughputSamples.ToList();
        Assert.All(eventSamples, s => Assert.True(s.Timestamp > DateTime.MinValue,
            "All throughput samples should have valid timestamps"));

        Output.WriteLine($"✓ Phase 1 (Publish): {report.Results.Phase1Publish.ThroughputEventsPerSec:F2} events/sec");
        Output.WriteLine($"✓ Phase 2 (Consume): {report.Results.Phase2Consume.ThroughputEventsPerSec:F2} events/sec");
        Output.WriteLine($"✓ Event Test: Collected {eventSamples.Count} throughput samples");

        // ====================================================================
        // ASSERT - PHASE 3: API LOAD TEST
        // ====================================================================

        // Verify API test ran for approximately specified duration
        var actualApiDuration = report.Results.Phase3Api.DurationSeconds;
        Assert.InRange(actualApiDuration, 9, 12,
            "API test should run for approximately specified duration (10s ±2s)");

        // Verify API metrics collected
        Assert.True(report.Results.Phase3Api.TotalRequests > 0,
            "API test should have processed requests");
        Assert.True(report.Results.Phase3Api.ThroughputCallsPerSec > 0,
            "API throughput should be positive");

        // Verify no errors during API test
        Assert.Equal(100.0, report.Results.Phase3Api.SuccessPercentage);
        Assert.Equal(0, report.Results.Phase3Api.ErrorCount);

        // Verify API throughput samples collected
        Assert.NotEmpty(report.ApiThroughputSamples);

        Output.WriteLine($"✓ Phase 3 (API Load): {report.Results.Phase3Api.ThroughputCallsPerSec:F2} req/sec");
        Output.WriteLine($"✓ API Load: {report.Results.Phase3Api.TotalRequests} total requests, 0 errors");

        // ====================================================================
        // ASSERT - RESOURCE MONITORING (All Phases)
        // ====================================================================

        // Verify process resource metrics collected
        Assert.NotEmpty(report.ProcessResourceSamples);

        // Verify RabbitMQ metrics collected
        Assert.NotEmpty(report.RabbitMqResourceSamples);

        // Verify PostgreSQL metrics collected
        Assert.NotEmpty(report.PostgresResourceSamples);
```

## Queue Purging Pattern

> **CRITICAL:** This pattern prevents flaky tests caused by stale events in durable queues.
> See [FLAKY_TEST_ANALYSIS.md](../../src/PerformanceTester.Orchestration.IntegrationTests/FLAKY_TEST_ANALYSIS.md) for detailed root cause analysis.

### Problem

The `ConfigurableReferenceService` uses a **durable queue** (`configurablereferenceservice-input`) that:
- Persists across test sessions
- Receives events from the shared exchange (`referenceservice.comparison`)
- Accumulates stale events from previous tests

When tests run after `OrchestratorCompleteWorkflowTests` (which publishes 500 events), the queue contains stale events that cause `ConfigurableReferenceService` to trigger prematurely.

### Solution: Queue Purging in All Tests

**All orchestration tests** must purge the ConfigurableReferenceService queue in their `finally` block:

```csharp
try
{
    // ... test logic ...
}
finally
{
    // CRITICAL: Purge ConfigurableReferenceService queue to prevent stale events
    // from affecting subsequent tests. Events published to the shared exchange
    // are routed to ALL bound queues, including this one if it exists.
    await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
}
```

**Tests using ConfigurableReferenceService** must also purge **BEFORE** connecting:

```csharp
try
{
    // CRITICAL: Purge BEFORE connecting to remove stale events
    await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);

    // Now safe to connect
    await System.ConfigurableReferenceService.ConnectAndSubscribeAsync(listenPort: config.ServicePort);
    // ... test logic ...
}
finally
{
    await System.ConfigurableReferenceService.DisconnectAsync();
    await System.RabbitMQ.PurgeQueueAsync(ConfigurableReferenceService.DefaultInputQueueName);
}
```

### Named Constant

`ConfigurableReferenceService.DefaultInputQueueName` provides the queue name:

```csharp
/// <summary>
/// Default queue name for ConfigurableReferenceService input events.
/// Tests should purge this queue at the end to prevent stale event accumulation.
/// </summary>
public const string DefaultInputQueueName = "configurablereferenceservice-input";
```

## Test Execution Strategy

### Sequential Execution (MANDATORY)

**All tests MUST run sequentially** - parallelization is NOT supported.

**File:** `AssemblyInfo.cs`

```csharp
using Xunit;

// MANDATORY: Disable test parallelization
// These tests share critical resources that cannot be isolated:
// - RabbitMQ queues (all tests publish to same queue)
// - Database (all tests use dotnet9aot_perftest_integrationtest_db)
// - Port 8093 (only one .NET AOT service instance can bind)
// - Service state (some tests require service running, one requires it NOT running)
[assembly: CollectionBehavior(DisableTestParallelization = true)]
```

**Why Sequential Execution is MANDATORY:**

1. **RabbitMQ Queues are Shared**

   - All tests publish to `instrument.status.changed` queue
   - All tests consume from `instrumentstatus.kpi.updated` queue
   - Events from parallel tests would mix together
   - Event counts would be wrong for all tests

2. **Database is Shared**

   - ALL tests use the same database: `dotnet9aot_perftest_integrationtest_db`
   - No per-test database isolation
   - Concurrent writes would interfere with each other

3. **Port 8093 is Shared**

   - Only ONE .NET AOT service instance can bind to port 8093
   - Multiple tests starting service simultaneously = bind failures

4. **Service State Conflicts**
   - `RunTestAsync_WhenServiceNotRunning_ShouldThrowTimeoutException` **REQUIRES port 8093 to be FREE**
   - All other tests **REQUIRE service to be RUNNING**
   - These requirements are mutually exclusive

**Benefits of Sequential Execution:**

- ✅ Easier debugging (clear test execution order)
- ✅ Clearer logs (no interleaved output)
- ✅ Reliable results (no resource contention)
- ✅ No flaky tests (deterministic execution)

### Test Execution Order

**Recommended execution order:**

1. **Complete Workflow Test** (~15-20 seconds) - Comprehensive happy-path verification

   - `RunTestAsync_CompleteWorkflow_ShouldExecuteAllPhasesSuccessfully` - Verifies all phases with detailed assertions

2. **Setup Phase Tests** (~2-3 seconds) - Service discovery error scenarios

   - `RunTestAsync_WhenServiceNotRunning_ShouldThrowTimeoutException` - Timeout when service not found

3. **Error Handling Tests** (~5-10 seconds) - Graceful failure scenarios

   - `RunTestAsync_WhenDatabaseUnavailable_ShouldFailGracefully` - Invalid database handling
   - `RunTestAsync_WhenConsumerTimeout_ShouldIncludeReceivedCount` - Consumer timeout with progress

4. **Cancellation Tests** (~2-3 seconds) - Graceful shutdown
   - `RunTestAsync_WhenCancelled_ShouldStopGracefully` - Cancellation token handling

**Total:** 5 integration tests

**Estimated Total Test Time:** ~25-40 seconds (sequential only)

**Key Improvement:** By consolidating 8 separate phase-specific tests into a single comprehensive workflow test, we:

- ✅ Reduce total test execution time (fewer service startups)
- ✅ Improve test maintainability (single source of truth for happy-path)
- ✅ Provide clearer test output (phase-by-phase progress logging)
- ✅ Reduce test infrastructure overhead (shared .NET AOT service instance)

## Questions & Decisions

### Q1: Why .NET AOT service instead of Go?

**Answer:**

- **Language alignment** - .NET orchestrator testing .NET service (consistent stack)
- **Team familiarity** - Easier to debug .NET-to-.NET interactions
- **Performance** - Native AOT provides ~50-100ms startup (comparable to Go)
- **Build time** - Paid once (~1-3 min), incremental builds faster
- **Dependencies** - .NET SDK already required for the project

### Q2: Should we test against multiple services (Go, Python, Rust)?

**Answer:** No. Integration tests verify orchestrator logic, not service implementations. Testing against one reliable service is sufficient. Python's `service-tester.py` already validates all 11 implementations.

### Q3: How to handle Docker container names in tests?

**Answer:** Use Testcontainers container names from `ContainerManager`:

- RabbitMQ: `"performancetest-rabbitmq"`
- PostgreSQL: `"performancetest-postgres"`

These match the actual container names started by `IntegrationTestBase`.

### Q4: Should tests clean up .NET AOT service database?

**Answer:** No. The orchestrator's `ExecuteSetupPhaseAsync` calls `IDatabase.ClearDatabaseAsync(config.DatabaseName)`, which clears the database before each test. Tests verify this cleanup works correctly.

**Note:** Tests use a dedicated database defined in `OrchestrationSystem.IntegrationTestDatabaseName` constant to isolate integration test data from production/manual testing.

### Q5: Can tests run in parallel?

**Answer:** No. Tests **MUST run sequentially** because they share critical resources:

1. **RabbitMQ queues** - All tests publish/consume from same queues
2. **Database** - All tests use `dotnet9aot_perftest_integrationtest_db`
3. **Port 8093** - Only one .NET AOT service instance can bind
4. **Service state** - One test requires service NOT running, others require it running

This is enforced via `[assembly: CollectionBehavior(DisableTestParallelization = true)]` in `AssemblyInfo.cs`.
