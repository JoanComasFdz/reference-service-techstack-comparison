# Plan: Add LINQ Extensions + Convenience Properties to Result

## Context

`EventCount.Create` and `WorkerCount.Create` both return `Result<T, string>`. We can chain them with LINQ comprehension syntax (`from...in...select`) and simplify unwrapping with `IsSuccess`/`IsFailure`/`Value`/`Error` properties on `Result`.

## Changes

### Step 1: Add convenience properties to `Result`

**File:** `src/JoanComasFdz.Result/Result.cs`

Add 4 properties to the `Result` partial record:

```csharp
public bool IsSuccess => this is Success;
public bool IsFailure => this is Failure;
public TSuccess Value => ((Success)this).Value;
public TFailure Error => ((Failure)this).Error;
```

`Value` and `Error` throw `InvalidCastException` if accessed on the wrong variant — safe when guarded by `IsSuccess`/`IsFailure`.

### Step 2: Add `ResultLinqExtensions.cs` to `JoanComasFdz.Result`

**New file:** `src/JoanComasFdz.Result/ResultLinqExtensions.cs`

Two extension methods enabling LINQ query syntax:

```csharp
public static Result<U, TError> Select<T, TError, U>(...)
public static Result<V, TError> SelectMany<T, TError, U, V>(...)
```

Both use the Dunet-generated `Match` internally.

### Step 3: Update TestCommand.cs — replace EventCount + WorkerCount parsing

**File:** `src/PerformanceTester.Cli/Commands/TestCommand.cs`

Replace the two if/is blocks:

```csharp
// Before (14 lines):
var eventCountResult = EventCount.Create(options.Events);
if (eventCountResult is Result<EventCount, string>.Failure ecf)
{
    consoleWriter.WriteError(ecf.Error);
    return 1;
}
var eventCount = ((Result<EventCount, string>.Success)eventCountResult).Value;

var apiWorkersResult = WorkerCount.Create(options.ApiWorkers);
if (apiWorkersResult is Result<WorkerCount, string>.Failure awf)
{
    consoleWriter.WriteError(awf.Error);
    return 1;
}
var apiWorkers = ((Result<WorkerCount, string>.Success)apiWorkersResult).Value;
```

```csharp
// After:
var parseResult =
    from eventCount in EventCount.Create(options.Events)
    from apiWorkers in WorkerCount.Create(options.ApiWorkers)
    select (eventCount, apiWorkers);

if (parseResult.IsFailure)
{
    consoleWriter.WriteError(parseResult.Error);
    return 1;
}
var (eventCount, apiWorkers) = parseResult.Value;
```

The remaining code (apiDuration, ValidateOptions, config building, etc.) stays unchanged.

### Step 4: Build and test

## Future Evolution

As more parameters get ported to value objects, the `select` builds `TestConfiguration` directly — no intermediate tuple:

```csharp
var parseResult =
    from eventCount in EventCount.Create(options.Events)
    from apiWorkers in WorkerCount.Create(options.ApiWorkers)
    from apiDuration in DurationParser.Parse(options.ApiDuration)
    from timeout    in DurationParser.Parse(options.InactivityTimeout)
    // ... more as they get ported
    select new TestConfiguration(
        EventCount: eventCount,
        ApiDuration: apiDuration,
        ApiWorkers: apiWorkers,
        InactivityTimeout: timeout,
        ...);

if (parseResult.IsFailure)
{
    consoleWriter.WriteError(parseResult.Error);
    return 1;
}
var config = parseResult.Value;
```

One LINQ chain parses everything, `select` assembles the config, one `IsFailure` check, one `config` variable. Scales cleanly regardless of parameter count.
