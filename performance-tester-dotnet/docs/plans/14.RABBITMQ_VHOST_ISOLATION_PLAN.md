# 14. RabbitMQ Vhost Isolation for Integration Tests

## Problem Statement

The test `RunTestAsync_WhenCancelledDuringEventPhase_ShouldStopGracefully` is failing with:

```
Assert.ThrowsAny() Failure: Exception type was not compatible
Expected: typeof(System.OperationCanceledException)
Actual:   typeof(System.InvalidOperationException)
---- System.InvalidOperationException : Failed to purge 9 out of 29 queues
```

**Root Cause:** Tests share the default RabbitMQ vhost (`/`), causing:

- Queue name collisions across tests
- Cross-test event contamination
- Failed cleanup operations (can't purge queues from other tests)
- Non-deterministic test failures

## Proposed Solution: Per-Test RabbitMQ Vhost Isolation

Each integration test gets its own RabbitMQ virtual host (vhost), providing **complete namespace isolation** for:

- Exchanges
- Queues
- Bindings
- Connections

This eliminates cross-test contamination entirely.

```
ContainerManager.RabbitMqConnectionString
    ↓

    ↓

    ↓
RabbitMQ class (stores connection string)

```


(No vhost specified = default `/` vhost)

## Proposed Architecture

### New RabbitMQ Vhost Connection Flow

```
ContainerManager.RabbitMqConnectionString (base, no vhost)
    ↓
IntegrationTestBase.InitializeAsync()
    ↓
    [NEW] Generate unique vhost name: "test_{testClass}_{testMethod}_{timestamp}"
    [NEW] Create vhost via Management API
    [NEW] Append vhost to connection string: amqp://user:pass@host:port/{vhost}
    ↓
System.InitializeAsync(rabbitMqConnectionString with vhost)
    ↓
RabbitMQ class (stores connection string WITH vhost)
    ↓
TSystem.InitializeSystemAsync()
    ↓
ConfigurableReferenceService(connectionString)  # Automatically uses vhost
    ↓
IntegrationTestBase.DisposeAsync()
    ↓
    [NEW] Delete vhost via Management API (cleanup)
```

### Vhost-Aware Connection String Format

```
amqp://testuser:testpass@localhost:20001/test_OrchestratorCancellationTests_WhenCancelledDuringEventPhase_2025_NOV_24_15_05_33
```

**Timestamp Format:** `yyyy_MMM_dd_HH_mm_ss` (e.g., `2025_NOV_24_15_05_33`)

- Human-readable for debugging
- Easy to identify when a test ran
- Unique enough for test isolation (second precision)

### Phase 1: Extend RabbitMQ Class with Vhost Management

**File:** `PerformanceTester.IntegrationTesting/RabbitMQ.cs`

Add new methods for vhost lifecycle:

```csharp
/// <summary>
/// Creates a new vhost via the RabbitMQ Management API.
/// </summary>
public async Task CreateVhostAsync(string vhostName);

/// <summary>
/// Deletes a vhost via the RabbitMQ Management API.
/// All exchanges, queues, and bindings within the vhost are automatically deleted.
/// </summary>
public async Task DeleteVhostAsync(string vhostName);

/// <summary>
/// Sets permissions for a user on a vhost via the Management API.
/// Required after creating a vhost so connections can use it.
/// </summary>
public async Task SetVhostPermissionsAsync(string vhostName, string username);

/// <summary>
/// Creates a new connection string with the specified vhost appended.
/// </summary>
public static string WithVhost(string baseConnectionString, string vhostName);
```

**Implementation Notes:**

- Uses RabbitMQ Management API (HTTP PUT/DELETE)
- Vhost name must be URL-encoded in API path
- Permissions must be set for the user after vhost creation
- Cleanup via `DeleteVhostAsync` removes ALL resources in vhost

**File:** `PerformanceTester.IntegrationTesting/VhostIsolatedSystem.cs` (NEW)

```csharp
/// <summary>
/// Base system class that provides per-test RabbitMQ vhost isolation.
/// Each test gets its own vhost, ensuring complete event isolation.
/// </summary>
public abstract class VhostIsolatedSystem : System
{
    /// <summary>
    /// The unique vhost name for this test instance.
    /// </summary>
    public string VhostName { get; private set; } = null!;

    /// <summary>
    /// Called by IntegrationTestBase to set up vhost before InitializeAsync.
    /// </summary>
    internal async Task SetupVhostAsync(
        string testClassName,
        string testMethodName,
        string baseConnectionString,
        int managementPort)
    {
        // Generate unique vhost name with human-readable timestamp
        var timestamp = DateTime.UtcNow.ToString("yyyy_MMM_dd_HH_mm_ss");
        VhostName = $"test_{testClassName}_{testMethodName}_{timestamp}".Substring(0, 63);

        // Create vhost via Management API
        // Set permissions for testuser
    }

    /// <summary>
    /// Called by IntegrationTestBase to clean up vhost after DisposeAsync.
    /// </summary>
    internal async Task TeardownVhostAsync(int managementPort);
}
```

### Phase 3: Update IntegrationTestBase to Support Vhost Isolation

**File:** `PerformanceTester.IntegrationTesting/IntegrationTestBase.cs`

```csharp
public abstract class IntegrationTestBase<TSystem> : IAsyncLifetime where TSystem : System
{
    public virtual async Task InitializeAsync()
    {
        await s_containers.EnsureStartedAsync(Output);

        // NEW: If system supports vhost isolation, set it up
        if (System is VhostIsolatedSystem vhostSystem)
        {
            var testContext = GetTestContext(); // Get test class/method names
            await vhostSystem.SetupVhostAsync(
                testContext.ClassName,
                testContext.MethodName,
                s_containers.RabbitMqConnectionString,
                s_containers.RabbitMqManagementPort);

            // Initialize with vhost-specific connection string
            var connectionStringWithVhost = RabbitMQ.WithVhost(
                s_containers.RabbitMqConnectionString,
                vhostSystem.VhostName);

            await System.InitializeAsync(
                s_containers.PostgresConnectionString,
                connectionStringWithVhost,
                s_containers.RabbitMqManagementPort,
                Output);
        }
        else
        {
            // Legacy behavior for non-vhost systems
            await System.InitializeAsync(
                s_containers.PostgresConnectionString,
                s_containers.RabbitMqConnectionString,
                s_containers.RabbitMqManagementPort,
                Output);
        }
    }

    public virtual async Task DisposeAsync()
    {
        System.Dispose();

        // NEW: Clean up vhost after test
        if (System is VhostIsolatedSystem vhostSystem)
        {
            await vhostSystem.TeardownVhostAsync(
                s_containers.RabbitMqManagementPort);
        }
    }

    /// <summary>
    /// Gets the current test context (class name, method name).
    /// Uses xUnit's ITestOutputHelper or reflection.
    /// </summary>
    private TestContext GetTestContext();
}
```

## Detailed Implementation: RabbitMQ Vhost API

### Create Vhost

```http
PUT /api/vhosts/{vhost_name}
Authorization: Basic dGVzdHVzZXI6dGVzdHBhc3M=
Content-Type: application/json

{}
```

### Set Permissions

```http
PUT /api/permissions/{vhost_name}/{username}
Authorization: Basic dGVzdHVzZXI6dGVzdHBhc3M=
Content-Type: application/json

{
  "configure": ".*",
  "write": ".*",
  "read": ".*"
}
```

### Delete Vhost

```http
DELETE /api/vhosts/{vhost_name}
Authorization: Basic dGVzdHVzZXI6dGVzdHBhc3M=
```

**Note:** Deleting a vhost automatically deletes all exchanges, queues, bindings, and connections within it.

## Benefits

| Aspect                       | Before (Shared Vhost)           | After (Per-Test Vhost)        |
| ---------------------------- | ------------------------------- | ----------------------------- |
| **Isolation**                | Weak (unique queue names)       | Complete (separate namespace) |
| **Cleanup**                  | Complex (must track all queues) | Simple (delete vhost = done)  |
| **Cross-Test Contamination** | Possible                        | Impossible                    |
| **Parallel Test Execution**  | Risky                           | Safe                          |
| **Connection Management**    | Manual close required           | Auto-cleanup on vhost delete  |
| **Queue Name Collisions**    | Must use unique names           | Any name works                |

## Risks and Mitigations

### Risk 1: Management API Authentication

**Risk:** Management API uses different credentials than AMQP.

**Mitigation:** Use same credentials (`testuser:testpass`) for both. The ContainerManager already configures this.

### Risk 2: Vhost Creation Latency

**Risk:** Creating vhost adds overhead per test.

**Mitigation:**

- Vhost creation is fast (~10-50ms via HTTP API)
- Much faster than current "close all connections" approach
- Cleanup is also faster (single DELETE vs multiple purges)

### Risk 3: Vhost Name Length Limit

**Risk:** RabbitMQ vhost names have a 255-character limit.

**Mitigation:** Truncate generated names to 63 characters (safe margin):

```csharp
var timestamp = DateTime.UtcNow.ToString("yyyy_MMM_dd_HH_mm_ss");
VhostName = $"test_{testClass}_{testMethod}_{timestamp}".Substring(0, 63);
```

### Risk 4: Test Context Discovery

**Risk:** Getting test class/method name from xUnit.

**Mitigation:** Use `ITestOutputHelper` type name or reflection on test class.
