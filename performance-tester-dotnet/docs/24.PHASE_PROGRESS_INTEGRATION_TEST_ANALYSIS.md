## Priority Classification

### Priority Levels

- **P0 - Critical:** Tests with known flakiness or race conditions that should be fixed immediately
- **P1 - High:** Tests with timing dependencies that could become flaky under load
- **P2 - Medium:** Tests with fixed delays that work but could be more deterministic
- **P3 - Low:** Tests with minor timing patterns that are unlikely to cause issues
- **P4 - None:** Tests with no timing concerns

## Infrastructure Files with Timing Issues

### OrchestrationSystem.cs - WaitForServiceHealthyAsync()

**Location:** `src/PerformanceTester.Orchestration.IntegrationTests/Infrastructure/OrchestrationSystem.cs`

**Priority:** P2

**Current Pattern:**
```csharp
public async Task WaitForServiceHealthyAsync(int port, TimeSpan? timeout = null, TimeSpan? retryInterval = null)
{
    var actualTimeout = timeout ?? TimeSpan.FromSeconds(10);
    var actualRetryInterval = retryInterval ?? TimeSpan.FromMilliseconds(200);
    
    while (DateTime.UtcNow - startTime < actualTimeout)
    {
        try
        {
            var response = await httpClient.GetAsync(healthUrl);
            if (response.IsSuccessStatusCode)
                return;
        }
        catch { }
        await Task.Delay(actualRetryInterval);  // ← POLLING
    }
    throw new TimeoutException(...);
}
```

**Issue:** Polling with fixed 200ms delays - not phase-aware

**Recommendation:** Could be enhanced if service reported "ready" phase, but current implementation works adequately for test setup.

## Implementation Recommendations

### For Orchestration Tests (P1 items 1-2)

These can be fixed immediately using the existing `PhaseAwaiter`:

```csharp
// Example: OrchestratorApiAbortTests.cs
var phaseAwaiter = new PhaseAwaiter();
var report = await orchestrator.RunTestAsync(config, progress: phaseAwaiter);

// Instead of: Assert.True(report.Results.Phase3Api.DurationSeconds < expected)
// Use: Verify the abort happened via phase events
Assert.Contains(phaseAwaiter.ReceivedPhases, 
    p => p.Phase == TestPhase.ApiTest && p.State == PhaseState.Failed);
```

### For Other Slices (P1 items 3-5, P2 items)

These require extending `IProgress<T>` to the respective services:

1. **EventConsuming:** Add `IProgress<ConsumerPhaseInfo>` to `IEventConsumer`
2. **DockerMonitoring:** Add `IProgress<DockerPhaseInfo>` to `IDockerMonitor`
3. **ProcessMonitoring:** Add `IProgress<ProcessPhaseInfo>` to `IProcessMonitor`

Each would follow the same pattern as the orchestration implementation.
