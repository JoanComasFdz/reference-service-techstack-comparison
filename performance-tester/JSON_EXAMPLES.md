## Key Observations from Examples

### Timestamp Precision
- Main report: `YYYY-MM-DD HH:MM:SS` (no microseconds)
- Samples: `YYYY-MM-DDTHH:MM:SS.ffffff+00:00` (microseconds + timezone)

### Decimal Places
- Time seconds: 3 places (0.500, 39.223)
- Throughput: 2 places (450.00, 124.00)
- CPU/Memory: 2 places (23.86, 256.75)
- Percentages: 1 place (38.10, 100.0)
- Response time: 3 places (1.992, 8.065)

### Data Types
- Counts (pid, threads, total_events): integers
- Measurements (cpu_percent, memory_mb): floats with fixed decimals
- Strings: quoted values like "pythonreferenceservice"
- Booleans: `true` (lowercase)

### Summary Calculations
```
avg = sum(values) / count
peak = max(values)
min = min(non_zero_values)  // for throughput
std_dev = sqrt(sum((x - mean)^2) / (n - 1))  // sample
cv = (std_dev / mean) * 100
response_time_ms = 1000.0 / throughput_per_second
```

### Optional Fields
- `phase_timestamps`: Included only if available
- `monitored_process`: Included only if process monitoring ran
- `wsl_version`: Included only if running in WSL
- `windows_host_total_ram_mb`: Included only in WSL2 with successful Windows query
- `disks`: Array can be empty if no disks found

## Validation Checklist

When generating these files from .NET:

- [ ] File names match pattern exactly: `test-report-{YYYYMMDD_HHMMSS}-{lowercase_name}.{suffix}`
- [ ] JSON uses 2-space indentation
- [ ] All timestamps use correct format (YYYY-MM-DD HH:MM:SS or ISO 8601)
- [ ] Numeric precision matches: 3 for time, 2 for throughput/cpu/mem, 1 for percentages
- [ ] All numeric values are numbers, not strings
- [ ] Standard deviation uses sample formula (n-1)
- [ ] Mode calculated by rounding to nearest integer first
- [ ] CV% = (std_dev / mean) * 100
- [ ] Min excludes zeros for throughput metrics
- [ ] All containers/processes that exist have report files
- [ ] WSL2 detection works and Windows queries are attempted
- [ ] Disk filtering works (>= 500GB only)
